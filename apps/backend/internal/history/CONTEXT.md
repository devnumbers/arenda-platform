# История

Продуктовая лента «История действий» по объектам: записи о ручных действиях пользователей, человекочитаемые строки, поиск и фильтры. Читают владелец и участники объекта (включая «Просмотр»); suspended-доступ в ленту не пускается. См. ADR 0061 (docs/adr/0061-action-history.md).

## Language

**История действий / Action History**:
Продуктовая лента действий по объектам для владельца и участников. Пишутся только ручные действия пользователя, в транзакции действия, безусловно для всех объектов. Переживает отзыв/выход участника; при удалении объекта удаляется вместе с ним (записей об удалении объекта не существует — они каскадятся вместе со всеми). Не путать с «Журналом действий» — это аудит для админки (контекст Audit, ADR 0020).
_Avoid_: журнал действий (это аудит), аудит, лог, event log

**Запись истории / History Entry**:
Одна строка ленты, append-only: вид действия, конкретное действие, основное действие, актёр (со снапшотом имени), сегменты текста, снапшот названия сущности, время. Запись неизменяема и не перечитывает сущность: снапшоты фиксируются при действии и живут вечно, у удалённой сущности остаётся строка без перехода. Каждая строка привязана к объекту (FK CASCADE): мутации без объектной привязки — карточка контакта «без объекта», задачи-правила книги «без объекта» (ADR 0052) — строк не пишут, как и системные действия.

**Основное действие / Base Action**:
Одна из четырёх групп фильтра ленты, каждой — своя иконка и цвет: **Добавление** (зелёный), **Изменение** (жёлтый), **Выполнение** (синий), **Удаление** (красный). Маппинг редких действий: архив/анархив объекта, пауза/снятие паузы платежа, возврат задачи в работу, продление аренды — «Изменение»; удаление операции («Отменённая операция») — «Удаление».

**Вид действия / Action Kind**:
Семь групп словаря журнала, группы чекбоксов фильтра: Объект, Аренда, Платежи, Операции, Контакты, Задачи, Участники.

**Сегменты строки / Row Segments**:
Текст записи, собранный сервером при записи: упорядоченные фрагменты, часть — со ссылкой на сущность (синие переходы на существующие страницы сущностей, тикет #713). Сервер — единственный источник текста строки; поиск ищет по конкатенации сегментов. Актёр в тексте не живёт — он поле записи, фронт группирует им.
_Avoid_: шаблоны на фронте

**Снапшот названия / Label Snapshot**:
Человекочитаемое название сущности (объекта, платежа, операции, контакта, задачи, участника) на момент действия. Пишутся имена и названия, почты участников (видны всем участникам, решение 2026-09-20), значения характеристик, роли и периоды. Не пишутся: телефоны контактов; суммы не попадают в текст (хранятся только структурой в payload, копейками).

**Актёр / Actor**:
Пользователь, совершивший действие: владелец или участник объекта (роль — owner/full_access/viewer, паттерн аудита ADR 0020). Системных записей в MVP нет: слотовые приостановки/восстановления доступа и активация приглашения при регистрации не пишутся (решение владельца 2026-09-22); авто-оплаты и авто-задачи не пишутся по уставу карты.

**Чтение / Read** (тикет #708):
`GET /history` — двусторонний keyset по (created_at, id) DESC: `before_cursor` ведёт в прошлое, `after_cursor` — prepend свежих записей; фильтры периода/основных действий/видов/актёров/объектов; поиск q — маршрутизация trgm/fts/both на сервере (решение #705). Область чтения — SQL-функция `actor_can_read_history` (000137): владелец при любом статусе объекта, участник — только неархивных; suspended и чужие объекты строк не отдают, а чужой/неизвестный id в property_ids — privacy-404 всего запроса (канон ленты задач #547). `GET /history/filters` — опции шита: участники = владелец и текущие ∪ все актёры журнала области (отозванные остаются фильтруемыми; обезличенные записи актёром-фильтром не становятся).
