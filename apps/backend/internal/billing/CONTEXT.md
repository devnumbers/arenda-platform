# Billing

Тарифы, подписки, способы оплаты и интеграция с Т-Кассой. Оплата подписки — платёжный мир Т-Кассы (Processing-словарь, ADR 0036), а не учёт по объектам.

## Language

### Подписка

**Тариф / Tariff Plan**:
План подписки, который задаёт лимит активных объектов и стоимость.
_Avoid_: план, пакет

**Подписка пользователя / User Subscription**:
Состояние тарифа пользователя. Подписка может быть платной для собственника или служебной для админа.
_Avoid_: аккаунт-план

**Служебная подписка / Service Subscription**:
Подписка, назначенная админом без оплаты: тариф действует фиксированный срок, оплат нет, автопродление выключено; по истечении срока — переход на базовый тариф. Назначение перезаписывает текущую подписку (оплаченный остаток не стакается); апгрейд поверх служебной делает подписку платной.
_Avoid_: бесплатная подписка, ручная подписка

**Оплата подписки / Subscription Payment**:
Денежное событие оплаты тарифа собственника через платёжного провайдера. Относится к подписке и не является финансовой операцией по объекту. Платёж хранит снимок маски карты, которой был оплачен: при MIT-списании — с метода, на который идёт списание, при финализации — из уведомления провайдера, поэтому история платежей остаётся осмысленной после удаления способа оплаты.
_Avoid_: платёж за тариф

**Срок жизни платёжной формы / Payment Form TTL**:
Абсолютный момент истечения (`expires_at`) оплаты подписки, инициированной пользователем: вычисляется при создании платежа из константы модуля, хранится на платеже и передаётся провайдеру тем же значением (`RedirectDueDate` Т-Кассы), так что обе стороны закрывают форму в один момент; у платежей без формы (MIT-списание) срока нет, и тарифное решение они не держат. Пока платёж жив (статус `pending`, срок не истёк) — он один на пользователя и держит его тарифное решение: другая смена тарифа и отключение подписки отвечают 409 `pending_payment_exists`, повторный запрос того же тарифа и периода возвращает существующий платёж. Истечение — серверная истина: воркер помечает платёж `failed` с кодом `form_expired`, выбор разблокируется, подписка не меняется. Успех, опоздавший после истечения, сверяется со статусом провайдера (ADR 0010): подтверждённый применяется, если платёж новее последней применённой, и фиксирует деньги только на платеже, если устарел.
_Avoid_: таймаут ссылки, срок жизни подписки

**Статусы подписки / Subscription Status**:
- `active` — подписка оплачена или бесплатная, изменения данных разрешены.
- `grace` — не удалось списать платёж за продление, отсрочка для повторной попытки или смены способа оплаты; изменения данных временно разрешены.
- `cancelled` — подписка отменена пользователем; автопродление отключено, но изменения данных доступны до конца оплаченного периода. Пока период оплачен, отмену снимает бесплатное возобновление; истёкший период восстанавливается только оплатой тарифа.
_Avoid_: состояние подписки

**Возобновление подписки / Resume**:
Бесплатное снятие отмены при действующем оплаченном периоде (тикет #617): подписка возвращается в `active`, автопродление включается, оплаченный остаток сохраняется, деньги не списываются. Выполняется одним доменным переходом с причиной `resumed` (инициатор — пользователь); включение автопродления на отменённой через правку автопродления остаётся отклонённым. Восстановление истёкшего периода — не возобновление, а платная реактивация через оплату тарифа.
_Avoid_: реактивация, повторная оплата, продление

**Выбор объекта при отключении / Keep Property**:
Свойство отмены (тикет #617): пользователь называет объект, который выживет при применении базового лимита, когда отменённая подписка истечёт и воркер переведёт её на базовый тариф; лишние активные объекты архивируются. Выбор валидируется (объект владельца и активный — иначе 409 `invalid_keep_property`), хранится на подписке и поглощается первым переходом, который делает его бессмысленным (падение на базовый, возобновление, платная реактивация, назначение служебной); устаревший выбор (объект заархивирован) заменяет правило «выживает последний обновлённый».
_Avoid_: сохранение объекта, защита объекта

**История переходов подписки / Subscription Transition Log**:
Неизменяемая запись каждого изменения состояния подписки (статус, тариф) с причиной и инициатором (пользователь, админ, система). Инструмент разбора инцидентов для админа; не путать с журналом аудита (ADR 0020), который записывает действия акторов.
_Avoid_: аудит подписки, журнал изменений

**Автопродление / Auto Renew**:
Настройка подписки, при которой по окончании оплаченного периода списывается плата за тот же тариф и период продлевается.
_Avoid_: автосписание, пролонгация

**Апгрейд / Upgrade**:
Смена тарифа на более дорогой. Выполняется сразу после успешной оплаты, стоимость рассчитывается по полной цене нового тарифа, срок действия отсчитывается от момента оплаты.
_Avoid_: повышение тарифа

**Даунгрейд / Downgrade**:
Смена тарифа на более дешёвый. Не требует немедленной оплаты, вступает в силу в конце уже оплаченного периода. При даунгрейде, если количество активных объектов превышает лимит нового тарифа, система архивирует лишние объекты.
_Avoid_: понижение тарифа

**Льготный период / Grace Period**:
Срок после неудачного автосписания, в течение которого подписка остаётся в статусе `grace`: система автоматически повторяет списание по расписанию повторов, пользователь может обновить способ оплаты или оплатить вручную. Правки данных остаются доступны, но эффективный лимит объектов — 1 (выживает последний обновлённый, прочие активные биллинг архивирует при входе в grace, ADR 0055); заархивированные id — снимок-долг на подписке: применённая оплата (повтор, ручная «Оплатить тариф», апгрейд) восстанавливает в своей транзакции ровно этот снимок под лимит тарифа; не поместившийся в лимит остаток остаётся долгом до следующей оплаты. Истечение льготного периода переводит подписку на базовый тариф, долг снимается, grace-архив остаётся в архиве. Ручные архивации пользователя биллинг не трогает; повторный вход в grace перезаписывает снимок.
_Avoid_: отсрочка, пробный период

**Grace-события / Grace Events**:
События жизненного цикла льготного периода, которые billing публикует в контекст notifications после коммита перехода подписки: «вход в grace» (`GraceEntered` — немедленно при переходе) и «grace истекает» (`GraceExpiring` — воркер-фаза в окне [конец периода − опережение, конец периода), ровно один раз на окно; отметка `grace_reminded_at` сбрасывается при входе в новое окно). Публикация best-effort: ошибка логируется и никогда не откатывает и не блокирует платёжный переход.
_Avoid_: уведомления из payment-переходов напрямую, синхронная доставка внутри транзакции

**Возврат / Refund**:
Возврат оплаты подписки через платёжного провайдера — всегда на полную сумму, инициируется админом. Трёхфазная сага: резервирование платежа во внутренний статус `refunding` (защита от двойного возврата) → вызов провайдера вне транзакции → финализация. При ошибке провайдера резерв откатывается; неопределённый исход (возврат в полёте, частичная сумма от провайдера как аномалия) остаётся в `refunding` под сторожем reconciliation-воркера, который позже сверяется со статусом провайдера (по контракту порта частичный исход у провайдера сворачивается в `refunded`, ADR 0037). Финализация переведёт оплату в `refunded`; деньги возвращаются всегда. Сброс подписки на базовый тариф с архивацией избыточных объектов выполняется только если возвращённая оплата — источник текущего оплаченного периода (последняя применённая): возврат оплаты, перекрытой позднейшей успешной, не меняет тариф, период и историю переходов — только audit-запись с актёром-админом (вебхук/воркер — системой); откат резерва восстанавливает статус до возврата. Статус `partial_refunded` — устаревший, новые частичные возвраты не создаются. Возврат денег банком (chargeback, статусы провайдера `REVERSED`/`PARTIAL_REVERSED` после успешной оплаты) применяется теми же правилами через уведомление о возврате с инициатором-системой (тикет #432): сброс только с источника текущего периода, повторные доставки — идемпотентный no-op, конфликт с уже оформленным возвратом разрешается в пользу зафиксированного состояния.
_Avoid_: чарджбэк, отмена платежа

**Назначение платежа / Payment Purpose**:
Структурированное описание того, за что платёж (вид, тариф, период). Провайдерный адаптер строит из него текстовое описание платежа для плательщика — язык и ограничение длины остаются на стороне адаптера.
_Avoid_: описание платежа в приложении

**Порт платёжного провайдера / Payment Provider Port**:
Провайдерно-нейтральный исходящий порт в application-слое: суммы в копейках, идентификаторы платежа и клиента, явный инициатор операции (CIT/MIT), признак сохранения способа оплаты. Вся специфика провайдера (подписи, форматы, callback-URL, словари статусов и ошибок) — внутри адаптеров. Активен ровно один провайдер (ADR 0038).
_Avoid_: провайдер в application-слое, ветвление по провайдеру

**Синхронная обработка вебхука / Synchronous Webhook Processing**:
Применение платёжного уведомления провайдера в пределах HTTP-запроса с бюджетом ~8 с; ответ 200 — только после полной обработки (повторная доставка — идемпотентный no-op), при сбое — не-200, ретраи выполняет провайдер. Успешная оплата применяется одним швом для вебхука, воркера автопродления и сверки — вместе с соблюдением лимита тарифа (архивация избыточных объектов); устаревший успех — оплата старее последней применённой — no-op на подписке, деньги фиксируются только на оплате. Out-of-order «succeeded после failed» сверяется со статусом провайдера как источником истины (ADR 0010, ADR 0039).
_Avoid_: фоновая обработка вебхука, always-200

### Отображение (UI-copy)

Экранная надпись поверх доменных статусов; доменные термины и контракты не меняются (решение владельца, 11.09.2026, тикет #614).

- `cancelled` подписки — «Остановлен» (статус) / «Тариф X отключен» (подтверждения действий).
- grace-плашка — «Оплата не прошла».
- Пустая история оплат подписки — «Нет операций». Тарифный хаб называет историю «Операции» — UI-copy exception в CONTEXT-MAP.md.
- Метки и знаки статусов оплат (суммы в контракте всегда положительные, знак считает фронт): `pending` — «В ожидании» без знака; `refunding` — тоже «В ожидании» без знака; `succeeded` — «Выполнена» с «−»; `failed` — «Не выполнено» с «−» красным; `refunded` — «Возврат» с «+»; одна строка списка = один платёж.
- Строки карт — без банковского лейбла: «{cardSystem} •••• {последние 4 цифры displayMask}».

### Способы оплаты

**Способ оплаты / Payment Method**:
Сохранённый платёжный инструмент пользователя (например, привязанная карта). Для каждого пользователя может быть несколько способов оплаты, но активным — только один. Используется для автопродления подписки.
_Avoid_: карта, платёжный инструмент

**Сессия привязки карты / Card Binding Session**:
Инициированная привязка карты у провайдера: хранит RequestKey и срок жизни; по подтверждению создаёт способ оплаты, по отказу провайдера (валидно подписанный отказной вебхук — законный исход доставки, ответ 200 OK) или истечении срока — не создаёт ничего и помечается отклонённой. Заменяет собой плейсхолдер в токене способа оплаты.
_Avoid_: плейсхолдер карты, временная карта

**Активный тариф / Active Tariff**:
Тариф, доступный пользователям для выбора. Скрытый (неактивный) тариф остаётся в системе: ссылки на него сохраняются, но в списке тарифов он не показывается.
_Avoid_: включённый тариф

### Т-Касса (термины провайдера)

«Операция» и «платёж» в этой секции — термины Т-Кассы из мира процессинга (ADR 0036, docs/adr/0036-fintech-domain-language.md), а не Операция из Rental-контекста.

**CC (Card Credentials)**:
Платёж по введённым карточным данным; родительский платёж CC/COF-связки.
_Avoid_: платёж по карте

**COF (Credentials on File)**:
Платёж по сохранённым реквизитам (RebillId).
_Avoid_: платёж по токену

**CIT (Customer-Initiated Transaction)**:
Операция, инициированная покупателем.
_Avoid_: инициативный платёж

**MIT (Merchant-Initiated Transaction)**:
Операция, инициированная мерчантом (например, автопродление подписки).
_Avoid_: автоматический платёж

**RebillId**:
Идентификатор сохранённых реквизитов в Т-Кассе, выдаётся после родительского платежа с `Recurrent=Y`.
_Avoid_: токен реквизитов

**PaymentId**:
Идентификатор платежа в Т-Кассе, выдаётся в ответе `Init`.
_Avoid_: идентификатор транзакции

**RequestKey**:
Идентификатор запроса на привязку карты в Т-Кассе, возвращается `AddCard` и приходит в add-card webhook.
_Avoid_: ключ привязки

**NotificationURL**:
URL мерчанта для webhook-уведомлений Т-Кассы о статусах платежа.
_Avoid_: callback URL, webhook endpoint
