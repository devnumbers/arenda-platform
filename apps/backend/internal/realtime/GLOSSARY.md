# Realtime

Стрим изменений сущностей для открытых клиентов: бэк доставляет грубые кадры «у объекта изменилась сущность», фронт инвалидирует react-query и перечитывает живое. Контекст владеет эндпоинтом стрима, словарём сущностей и портом публикации; транспортные примитивы — общий платформенный `internal/platform/sse` (ADR 0060). Читают владелец и участники объекта; suspended и отозванные кадры перестают получать сами — аудитория считается на момент публикации. См. ADR 0062 (docs/adr/0062-realtime-entity-events.md).

## Language

**Событие изменения / Entity Changed**:
Грубый кадр стрима `entity.changed` о том, что у объекта изменилась сущность одной из категорий словаря. Данных сущности не несёт — клиент перечитывает состояние через API; стрим никогда не становится второй системой правды.
_Avoid_: уведомление (занято контекстом Notifications), payload-событие, пуш

**Грубый кадр / Coarse Frame**:
Кадр без тела сущности: конверт v1 (`{v, occurredAt, payload}` по ADR 0060 §5) с payload `{propertyId, entity}`; `propertyId` равен null для внеобъектных мутаций книжки владельца (контакты и задачи без объекта, пары InOwnerBook) — такой кадр доставляется только автору. Противоположность — точечный кадр с данными; точечные кадры в MVP не существуют.
_Avoid_: точечный кадр (нет в v1)

**Словарь сущностей / Entity Dictionary**:
Стабильные имена категорий изменений: payments, operations, tasks, contacts, rentals, property, access, history. Контракт бэк ↔ фронт: фронт маппит имя на префиксы семейств query-keys (одна категория может накрывать несколько семейств — `operations` накрывает операции платежей и глобальные операции, `access` накрывает и семейства объекта: хаб-список и пилюлю роли получателя гранта — #719). Добавление категории назад-совместимо.
_Avoid_: имена сущностей БД, названия таблиц

**Аудитория кадра / Frame Audience**:
Пользователи с производным доступом на чтение объекта на момент публикации (ADR 0028), включая автора изменения — его другие вкладки и устройства тоже ждут инвалидации, а вкладка-источник перечитывает идемпотентно. Смена/отзыв/приостановка доступа не управляют соединениями — отозванный просто перестаёт получать кадры.
_Avoid_: рассылка всем подключённым, исключение автора

**Точный потребитель / Precise Consumer**:
Экран, подписанный на кадры своей сущности через фронт-реестр `shared/api/realtime-subscriptions`: пока подписчики живы, кадр уходит только адресатам — подписчику, а не blanket-инвалидации семейств сущности, и вливается в первую страницу кэша вместо перечитывания окна (ADR 0062 §2, тикет #718). onOpen-перечитывание (открытие и переподключение стрима) подавлению не подлежит — окно потребителя реанкеруется целиком.
_Avoid_: отдельный стрим на сущность, подписка на бэке

**Публикация / Publication**:
Захват пар (сущность, объект) в транзакции-источнике через порт realtime и рассылка их носителем (см. ниже) строго после коммита, best-effort: упавший кадр логируется и никогда не валидирует и не откатывает мутацию. Дедуп на транзакцию: одна пара — один кадр (массовая операция шлёт один кадр, не N).
_Avoid_: публикация через доменный dispatcher, публикация до коммита

**Носитель / Carrier**:
Позднесвязанный в контексты-издатели инстанс порта Publisher: сервисы-издатели получают его сеттером `SetRealtimePublisher` (девять сеттеров — payments, tasks, contacts, rentals, properties, access; инстанс `realtimeCarrier` собирается в композиционном корне cmd/api/main.go), общий post-commit хвост `Dispatch` передаёт ему захваченные в транзакции пары для рассылки строго после коммита. Имя из ADR 0062 §3 «Carrier publication at the mutation seams».
_Avoid_: dispatcher (занято ADR 0014 — доменный in-memory dispatcher из пути убран), шина, брокер
