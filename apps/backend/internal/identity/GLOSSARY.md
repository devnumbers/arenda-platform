# Identity

Accounts, authentication, sessions, and user roles for Arenda Platform. The Owner and Admin roles thread through every other context.

## Language

### Роли

**Собственник / Owner**:
Пользователь сервиса, который управляет объектами, арендами, операциями, регулярными операциями, настройками напоминаний и подпиской. Канонический дом значений ролей — shared kernel `shared/actor` (ADR 0034); identity хранит реэкспорт.
_Avoid_: аккаунт, клиент

**Админ / Admin**:
Внутренний пользователь сервиса для поддержки. Админ не ведёт объекты и финансы за собственника, но может вести собственные тестовые данные для проверки тарифной логики.
_Avoid_: модератор, оператор

### Идентификаторы и профиль

**Телефон / Phone**:
Канонический номер российского мобильного в формате `+7XXXXXXXXXX`. Является логином: пользователь входит по номеру телефона.
_Avoid_: мобильный, контакт

**Email / Email**:
Адрес электронной почты, по которому доставляется логин-код. Нормализуется приведением к нижнему регистру; IDN/punycode-декодирование не применяется. Обязателен для аутентификации.
_Avoid_: почта (как синоним канала доставки), e-mail

**Подтверждённый email / Verified email**:
Email, чья принадлежность подтверждена доставкой и успешным вводом логин-кода. Имеет временную метку подтверждения. Первый код протокола смены email подтверждает текущий адрес, второй — новый; свободная правка адреса через профиль исчезла (#721), поэтому «смена сбрасывает подтверждение» больше не случается.
_Avoid_: верифицированный email, проверенный email

**Профиль / Profile**:
Персональные данные собственника: имя, фамилия, отчество и часовой пояс. Email в профиль не входит: адрес меняется только протоколом «Смена email», свободная правка исчезла (#721). Редактируется самим пользователем; часовой пояс меняется без побочных эффектов.
_Avoid_: личные данные, карточка пользователя

**Часовой пояс / Timezone**:
IANA-идентификатор часового пояса собственника (например, `Europe/Moscow`); по умолчанию Europe/Moscow. Фиксируется по устройству в момент регистрации (#451), далее меняется только вручную в профиле — тихой перезаписи не бывает. Задаёт «сегодня» тика материализации в контексте Payments (ADR 0048): смена пояса не переписывает историю — сдвигаются только будущие границы суток.
_Avoid_: таймзона, смещение UTC

### Аутентификация

**Аутентификация / Authentication**:
Вход в систему по номеру телефона и логин-коду, отправленному на привязанный email. Регистрация и вход объединены: если пользователя с подтверждённым телефоном+email ещё нет, он создаётся с ролью Собственник (ADR 0015).
_Avoid_: логин (как операция), авторизация, вход

**Смена телефона / Phone change**:
Операция смены номера телефона аутентифицированным собственником. Код подтверждения отправляется на текущий email, привязывается к новому номеру; при успехе старый номер освобождается, все сессии кроме текущей завершаются, окна попыток и старого, и нового номеров сбрасываются, и в той же транзакции планируется письмо-уведомление на текущий email (#1207).
_Avoid_: замена номера, редактирование телефона

**Смена email / Email change**:
Подтверждаемая смена адреса электронной почты аутентифицированным собственником: код на текущую почту — сервер проверяет его и выпускает грант; новый адрес — называется пользователем и привязывается к гранту, уходит код на новую почту; код на новую — шаг применяет адрес как подтверждённый, отзывает все сессии кроме текущей и планирует письмо-уведомление на прежний адрес — всё одним коммитом (решение #1207, перекрыло прежнее «сессии не трогаются»). Связка шагов — одноразовый грант ≈10 минут, без резюме между сессиями; лимит 5 отправок кода на новые адреса в час.
_Avoid_: замена почты, редактирование email, смена почты

**Грант смены email / Email change grant**:
Одноразовое серверное подтверждение того, что текущий адрес собственника проверен кодом. Выпускается в момент проверки текущего адреса; новый адрес привязывается к гранту следующим шагом операции. Живёт ≈10 минут с момента выпуска, привязан к пользователю (и к адресу после привязки), хранится хешем; у пользователя живёт не больше одного гранта, применение смены гасит грант.
_Avoid_: токен смены, билет

**Повторная отправка кода / Code resend**:
Переиздание и повторная доставка логин-кода по явному запросу с экрана для ещё не завершённой операции. На шаге «код на новую почту» якорь — живой грант (код текущей почты к этому моменту сожжён); переиздание стирает прежний неиспользованный код триплета, тратит часовой лимит на новые адреса и подчиняется троттлингу отправки, грант не расходует.
_Avoid_: респенд, повторный код

**Логин-код / Login code**:
Одноразовый 6-значный код подтверждения, отправляемый на email. Имеет TTL (`LoginCodeTTL`), используется один раз, хранится только в виде хеша, привязан к триплету phone+email+цель.
_Avoid_: пароль, SMS-код (доставка сейчас по email)

**Цель логин-кода / Login code purpose**:
Назначение кода, определяющее к чему он привязан и какую операцию подтверждает. Три значения: `login` — аутентификация, `phone_change` — смена телефона, `email_change` — смена email; код одной цели не проходит проверку для другой.
_Avoid_: тип кода, режим кода

**Шаг письма / Login code step**:
Адресная роль письма с кодом: у каждой операции своё письмо — уникальные шаблон и тема под свой кейс (#1204). Письма входа, смены телефона и шага «код на текущую почту» смены email уходят на текущий адрес (`current_email`), шаг «код на новую почту» — на новый адрес, привязанный к гранту (`new_email`). Пара цель+шаг выбирает шаблон и тему в канале доставки и не участвует в хеше кода.
_Avoid_: тип письма, канал письма

**Уведомление о смене контакта / Contact-change letter**:
Notification-only письмо о состоявшейся смене телефона или email (#1207, факты research #1201 §5): уходит в той же транзакции, что и смена (River-джоба, дубликат при ретрае допустим), только об успешных сменах; при смене email адресуется прежнему адресу, при смене телефона — текущему email (SMS-канала нет). Не содержит кода, ссылок-действий и нового адреса/номера; называет факт и время (в поясе пользователя) и блок «если это были не вы» → hello@rentlee.ru.
_Avoid_: security-письмо, алерт, письмо о смене (расплывчато), обратное письмо

**Throttle отправки / Send throttle**:
Доменное правило: код для того же триплета phone+email+цель нельзя перевыпустить раньше, чем через минуту после предыдущего; действующий код при этом не инвалидируется. Отказ троттла не тратит лимиты отправок (#1210) — тратятся только фактические выпуски, и потраченное не возвращается при неудачной доставке («каждая отправка считается», #720-3). Не путать с транспортным rate-limit.
_Avoid_: кулдаун, интервал отправки

**Лимит отправок на получателя / Recipient send limit**:
Анти-флуд правило (#1210, форма по OWASP «per-account basis»): не более 5 логин-кодов в час на один адрес электронной почты, суммарно по всем целям и инициаторам. Защищает чужой ящик от флуда при переборе телефонов и адресов; отказ — 429 без инвалидации действующего кода.
_Avoid_: анти-спам, бюджет адреса (бюджет — про смену email)

**Лимит отправок инициатора / Initiator send limit**:
Анти-флуд правило (#1210): не более 10 логин-кодов в час на одного пользователя-инициатора, суммарно по операциям смены телефона и email. Вход лимит не тратит: там пользователь кода — субъект, а не инициатор (поток неаутентифицирован, и счёт по нему позволил бы знающему телефон выжечь бюджет самого аккаунта).
_Avoid_: лимит пользователя, квота сессии

**Окно попыток / Attempt window**:
Sliding 30-минутное окно, считающее неудачные попытки ввода логин-кода и привязанное к номеру телефона (не к пользователю или email). После 15 неудач номер блокируется до истечения окна; при смене телефона окна и старого, и нового номеров сбрасываются. Перевыпуск кода окно не сбрасывает (NIST SP 800-63B-4 §3.2.2, тест в #1210).
_Avoid_: лимит, rate-limit (это доменное правило, а не транспортное)

### Сессии

**Сессия / Session**:
Server-side непрозрачный токен доступа, хранимый в PostgreSQL и доставляемый через `HttpOnly`-cookie (ADR 0004). Живёт по sliding-окну без абсолютного потолка: каждое использование продлевает срок на базовый TTL (7 дней) — активная сессия не истекает никогда (ADR 0056).
_Avoid_: токен, ключ

**Устройство / Device**:
Описание клиента, с которого открыта сессия: тип (компьютер, телефон, планшет, TV), браузер с мажорной версией, ОС и сырой User-Agent. Парсится один раз, при создании сессии; сырая строка хранится рядом, чтобы будущий перепарс не ждал перелогинов.
_Avoid_: гаджет, девайс

**Активная сессия / Active session**:
Строка списка устройств: сессия с устройством, последним IP, городом и временем последней активности. Владелец видит свои активные сессии и может завершить любую чужую или все, кроме текущей (#728); текущая завершается выходом. Текущая — сессия за кукой вызывающего; в grace-окно ротации (см. Ротация токена) она опознаётся и по прежнему токену. Ревокации пишутся в аудит по умолчанию (fail-safe, ADR 0020). На экранах строки зовутся «сеанс(ами)» — решение владельца 18.09.2026 (DESIGN.md §13); в домене — «сессия».
_Avoid_: список устройств (как термин сущности), устройство (как синоним сессии)

**Ротация токена / Token rotation**:
Замена токена сессии раз в 14 дней (renewal timeout, OWASP) — компенсация за отсутствие абсолютного потолка (ADR 0056). Новый токен и хеш атомарно заменяют старые; прежний токен короткое окно (2 минуты) принимается ради in-flight запросов, затем умирает.
_Avoid_: обновление токена, refresh

**Город сессии / Session city**:
Геолокация последнего IP сессии по оффлайн-базе DB-IP City Lite, локаль ru (fallback en). Фиксируется при создании и обновляется при смене IP; неизвестный или приватный IP не стирает сохранённый город. Смена IP без смены города переписывает только IP (ADR 0057).
_Avoid_: геолокация (как синоним города), локация

**Завершение сессии / Logout**:
Прекращение сессии пользователем. Три операции: завершение текущей сессии по текущему токену, ревокация одной чужой сессии и завершение всех сессий, кроме текущей — две последние живут на экране «Устройства» (#728). Завершения пишутся в аудит fail-open: запись не блокирует ответ (ADR 0020); ревокации — fail-safe: сбой аудита откатывает удаление (ADR 0056).
_Avoid_: выход, разлогин

**Фото профиля / Profile Photo**:
Одна фотография профиля пользователя (ADR 0065, карта #1217): максимум одна картинка — приватная, хранится в объектном хранилище под ключом `photos/<uuid>.<ext>` (колонки `photo_key` + `photo_content_type` в строке пользователя), выдача и загрузка стримят через бэкенд. Читает сам пользователь (`/api/v1/me/photo`) и — аменд 2026-10-09, решение владельца #1286 («показ участникам») — каждый, с кем его связывает хотя бы один объект, читаемый обеими сторонами (ADR 0028, симметрично): `GET /api/v1/users/{userId}/photo`; нет связи и нет фото — один 404. Наружу — только путь `photoUrl`.
_Avoid_: изображение, публичный URL фото
