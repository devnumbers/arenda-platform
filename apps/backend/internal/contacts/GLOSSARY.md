# Contacts

Bounded context книги контактов владельца: карточки людей, нужных для обслуживания объектов, — сантехник, управляющая компания, консьерж. Контакт — не пользователь сервиса: аккаунта нет и не подразумевается. Привязка к объекту опциональна; удаление объекта уносит привязанные контакты, в книге владельца остаются только контакты без объекта (ADR 0054 §2 в правке 2026-10-02, тикет #1049). «Объект» не переопределяется — см. properties/GLOSSARY.md.

## Language

**Контакт / Contact**:
Карточка человека для объекта: сантехник, управляющая компания, консьерж, диспетчер. Живёт в книге владельца; связь с объектом опциональна — контакт без объекта существует сам по себе. Не пользователь сервиса и не участник шаринга.
_Avoid_: контакт объекта (снесённая сущность Property Contact, ADR 0026), связь, абонент, арендатор

**Книга контактов / Contact Book**:
Все контакты владельца независимо от привязки к объектам. Контакты без объекта видит только владелец; привязанные к объекту видны и участникам шаринга — по ролям на объекте (ADR 0028). Плоский список книги (вся книга одним списком) отдаёт актёру объединённый срез: собственные карточки плюс привязанные к объектам, куда у актёра есть доступ, — для владельца это вся его книга, для участника — контакты доступных объектов и свои безобъектные. Видимость определяет привязка, а не книга: карточка, перенесённая на другой объект, остаётся в книге прежнего владельца. Список листается порциями keyset-курсором (#600): продолжение — последний ключ страницы (сортировочный ключ + id, для сортировки по объекту — впереди флаг «без объекта» и имя объекта, по созданию — момент создания, #847; курсор связан с сортировкой, чужой курсор — 400), поэтому карточка, созданная или удалённая между догрузками, не дублируется и не теряется; переименование или перенос уже пройденной карточки может увести её через границу окна — неотъемлемая цена видимой сортировки по имени/объекту (момент создания неизменен — карточка не уходит из пройденного окна). Пустые sort/order сервис нормализует в дефолт (имя/возрастание) до SQL — предикат окна и ORDER BY ветвятся по одним литералам.
_Avoid_: справочник контактов, общий список контактов, offset-окна книги

**Роль / Role**:
Текстовое поле контакта: кем человек приходится объекту — «сантехник», «консьерж». Не роль доступа: роли на объекте (Полный доступ, Просмотр) — язык контекста access, к контакту отношения не имеют.
_Avoid_: роль доступа (другой словарь), должность, тип контакта

**Мессенджер / Messenger**:
Пара полей контакта: название мессенджера (текст) и имя пользователя в нём. Одна пара на контакт.
_Avoid_: ник, телеграм (конкретный сервис — мессенджер любой), способ связи

**Заметка / Note**:
Свободный текст на контакте: что уточнить при звонке, ориентиры, код домофона.
_Avoid_: комментарий, описание

**Фото контакта / Contact Photo**:
Одна фотография карточки контакта (ADR 0065, карта #1217): максимум одна картинка на карточку — приватная, хранится в объектном хранилище под ключом `photos/<uuid>.<ext>` (колонки `photo_key` + `photo_content_type` в строке контакта), выдача и загрузка стримят через бэкенд. Доступ — как у самой карточки (ADR 0054): привязанная — по роли на объекте, без объекта — только владелец книги. Наружу — только путь `photoUrl` (`/api/v1/contacts/{id}/photo`).
_Avoid_: изображение, аватар контакта, публичный URL фото
