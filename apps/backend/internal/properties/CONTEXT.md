# Properties

Bounded context объектов. После удаления домена аренд и Операций (ADR 0046, тикет #436) контекст «только про объект»: карточка, фото, атрибуты, архив. Термины занятости (аренды, операции, сводки) из языка контекста ушли вместе с доменом; контакты ушли в отдельный контекст contacts (ADR 0054).

## Language

**Объект / Property**:
Минимальная единица учёта платформы: карточка объекта с атрибутами и фото. Контакты объекта живут в отдельном контексте contacts (ADR 0054); домен платежей (контекст payments, ADR 0047) проектируется поверх объектов отдельными спеками.
_Avoid_: квартира, жильё, недвижимость

**Автогенерация названия / Auto Name**:
Название объекта выводится из его типа, когда пользователь его не ввёл (карта #984, тикет #1001): «Мой/Моя/Моё + слово типа + серийник» — «Моя квартира 1», «Мой гараж 1», «Моё коммерческое помещение 1» (коммерческое — дословно как тип). Серийник — число объектов этого типа у владельца (активные и архивные, удалённые выпали) плюс один, правило Б владельца: после переименований и удалений номера могут повторяться и пропускаться — имена не уникальны и уникальными не становятся. Сам объект в счёт входит: очистка имени у единственной квартиры даёт «Моя квартира 2» — она уже вторая созданная (принято владельцем 30.09); после удаления счёт начинается заново с единицы. Генерирует бэк при создании (name в контракте create необязателен) и при правке с очищенным названием (`name: ""`); отсутствующий `name` в PATCH имя не трогает. Сгенерированное имя сохраняется как обычное название — дальше это просто имя объекта.
_Avoid_: дефолтное название, шаблонное имя, автонейм-плейсхолдер

**Характеристики объекта / Property Attributes**:
Пер-типовые типизированные характеристики объекта: число комнат, площади, этаж, год постройки и т.п. Набор характеристик определяется типом объекта (всего 11 типов; студия — карта #984, тикет #1003 — делит набор квартиры). Все характеристики необязательные. Ключи и значения — на английском; русские подписи показываются на фронте и в админке.
_Avoid_: атрибуты, параметры, спецификация

**Фото объекта / Property Photo**:
Фотография карточки объекта. Хранится в объектном хранилище, метаданные — в БД; до 10 фото по 5 МиБ на объект.
_Avoid_: изображение, картинка

**Активный объект / Active Property**:
Неархивный объект. Активные объекты считаются в тарифных лимитах.
_Avoid_: текущий объект

**Объект на ремонте / Property Maintenance**:
Промежуточный статус жизненного цикла (active → maintenance → active): ремонт без съёмщиков. Арендная пауза (карта #1047, тикет #1050): пока объект на ремонте, мутации незавершённой аренды запрещены — создание, правка условий (продление — тот же PATCH), завершение, удаление незавершённой; конвейер аренд отвечает 409 `property_maintenance` («Объект на ремонте — аренда недоступна») симметрично архивному гварду. Просмотр не блокируется: завершённые аренды (история) на ремонте видны и удаляются как раньше. Сами переходы active↔maintenance гвард не ограничивает: фронт-гард #628 завершает/удаляет аренду до перевода в ремонт, а незавершённая аренда, оставшаяся на ремонте прямым API-вызовом, разматывается «Завершить ремонт» — спасательный люк, специальных путей нет. Платежи и задачи на ремонте живут как на активном (их конвейеры чтят только архив) — гвард только арендный.
_Avoid_: «аренда на паузе» (аренда не ставится на паузу — она запрещена), блокировка объекта

**Архивный объект / Archived Property**:
Объект, скрытый из активных списков и доступный только для просмотра истории. Инвариант неизменяемости (карта #611, тикет #618): данные архивного объекта не редактируются никак — карточка, фото, пин, правила платежей, операции, аренды, задачи; открыт только жизненный цикл самого объекта (архивация/восстановление/удаление) и книга контактов владельца (ADR 0054). Мутация данных — 409 «Нельзя изменить архивный объект» во всех контекстах (исключение контекста access — решение #163); тики платежей и задач архивные объекты пропускают (ADR 0049, ADR 0051).
_Avoid_: удалённый объект, выключенный объект

**Основной объект / Primary Property**:
Глобальный признак «наверху списков» (карта #573, тикет #577; переосмыслен в терминах «основного» резолюцией #584): основной объект поднимается и в главном списке «Объекты», и на странице «Платежи объектов», и в сортировке «По статусу» всегда первый. Признак ставится на объекте — не пер-пользовательский; основных объектов может быть несколько. Хранится как `pinned_at`: NULL — не основной, момент времени — основной с того момента; порядок среди основных — по времени (первый отмеченный выше, повторная отметка время не меняет). Права — как у правки объекта (ADR 0028 `CanEdit`: владелец и полный доступ). Архивация снимает признак в том же обновлении (возвращённый из архива объект не основной); удаление уносит его вместе со строкой. Контракт API не переименовывается — поле и эндпоинт остаются `pinned_at` / `PUT /properties/{id}/pin` (решение тикета #585).
_Avoid_: пин, булавка, закреплённый, закрепление, избранное (избранное — про платежи)

**Занятость объекта / Property Occupancy**:
Вычисляемое состояние объекта из его единственной незавершённой аренды (подошла к концу / активная / будущая / нет) против «сегодня владельца» (ADR 0048); резолюция #584. Канон для группировки сортировки «По статусу», бейджей карточки и красной точки. Статусы без аренды — `none`; статус самого объекта (активный / на ремонте / архивный) — жизненный цикл, не занятость: объект с арендой на ремонте остаётся в своей арендной группе. Просрочка платежей для красной точки — язык payments (overdue), занятость её не дублирует.
_Avoid_: статус объекта (это жизненный цикл), загруженность, состояние аренды

**Удаление объекта / Property Deletion**:
Безвозвратное удаление объекта вместе со всеми его данными: аренды, платежи, операции, задачи и привязанные контакты объекта уносит каскад; в книге владельца остаются только контакты без объекта (ADR 0054 §2 в правке 2026-10-02 — разворот исходного «выживания», тикет #1049). Семантика — ADR 0049 (docs/adr/0049-payments-schema-tick-contracts.md), superseded ADR 0025: режимов удаления нет, «удалить только объект» не существует (решение владельца 12.09.2026, тикет #629). У объекта с незавершённой арендой удаление запрещено — сперва «Завершить аренду» (409 `property_occupied`, тикет #632); завершённые аренды сносятся вместе с объектом до строки объекта, чтобы RESTRICT аренды на её платёж не конкурировал с каскадом платежей.
_Avoid_: стирание, очистка объекта, частичное удаление, отсоединение данных

**Шаринг объекта / Property Sharing**:
Совместный доступ к объекту через участников и приглашения (контекст access). Роль актёра на объекте видна в карточке; превысившие лимит участника приостанавливаются. Access-контекст детали чужого объекта несёт имя владельца (owner_name, «никогда не почта») и — только на детали — почту владельца (owner_email, контактный ряд «Владелец объекта», Figma 2200-97365; сознательная экспозиция этого экрана, прецедент owner_email в suspended_shared #702). Жизненный цикл объекта (архив/возврат/удаление) — владельческий: участнику эти действия не предлагаются и на бэке 403 (CanLifecycle).
_Avoid_: совместное владение

**Поиск объектов / Property Search**:
Серверный текстовый поиск по видимой актёру срезе (свои + разделяемые с активным участием, без архивных): регистронезависимая подстрока по названию и адресу (карта #596, тикет #601, `GET /properties/search`). Окно — keyset-пагинация по (название, id) — паттерн #597; порядок по названию повторяет дефолтный порядок хаба. Отличать от поиска объектов на «Платежах» (`GET /payments/objects?search=`): тот фильтрует стопки платежей, не карточки.
_Avoid_: фильтр (фильтры хаба — клиентские, по типу/статусу), полнотекстовый поиск
