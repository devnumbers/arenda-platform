# DESIGN.md — дизайн-конвенции лендинга

Как строить и менять визуальный слой лендинга, чтобы он оставался 1:1 с
макетами и не расходился с кабинетом. Читать перед любой UI-работой;
визуальные решения поверх этого файла принимает только владелец. Файл
растёт вместе с продуктом: зафиксированное решение становится разделом
здесь — так же, как в `apps/frontend/DESIGN.md`.

Первоисточники: макеты Figma («📌 Рентли. Сервис и лендинг» — подписи
фреймов в `README.md`), токены `@theme` в `app/globals.css`, шрифт Onest.

## 1. Шрифты без CLS

Выбранный рецепт подключения шрифта (тикет #894, T6 — из вилки
«size-adjust или next/font/local» выбран базовый путь; механика в коде не
менялась, здесь только репозиторная фиксация выбора):

- **Preload двух основных срезов** Onest — cyrillic и latin — в шапке
  документа (`app/layout.tsx:37-50`, `crossOrigin` обязателен для
  шрифтового preload). Ext-срезы не предзагружаются — доезжают сами.
- **`font-display: swap`** в каждом `@font-face`
  (`app/globals.css:16/26/36/46`) — первый рендер текста не блокируется
  шрифтом.
- **`size-adjust` не применяется**: срезы — оригинальные css2 Google
  Fonts (тот же Onest v11, что у кабинета), метрики без смещений —
  выравнивать нечего, а ручной `size-adjust` увёл бы лендинг от
  кабинетного рендера.
- **`next/font/local` не используется**: четыре `@font-face` с
  `unicode-range` в globals.css; ext-срезы (cyrillic-ext, latin-ext)
  докатываются браузером при первом использовании глифов из их
  диапазона (см. комментарий `app/layout.tsx:35-36`) — эффект
  подгрузки по мере необходимости next/font не улучшает.
- **CLS = 0 подтверждён** Lighthouse-отчётом тикета #894 (прод-билд,
  throttled mobile; шрифтовый preload назван драйвером наряду с AVIF и
  `priority` hero).
- **Балансировка строк** (решение владельца 24.10): `h1–h6, p {
  text-wrap-style: balance }` глобально в `@layer base`
  (`app/globals.css`), ручные `text-balance` вычищены. На inline-узлах
  не действует, браузер ограничивает баланс 6 строками — длинные тексты
  остаются с естественным переносом. Каскад достаёт и портативный UI
  (`components/ui`, модалка фидбека): тексты там короткие — нейтрально,
  сами компоненты не менялись.

Обновление шрифта — скачать свежие срезы css2 и заменить файлы вместе с
диапазонами `unicode-range` (комментарий `app/globals.css:3-8`).

## 2. Ярусы по ширине окна

Три яруса, граница — ширина **окна**, не устройство (панель in-app браузера
уже 1200 показывает планшетный ярус): мобайл ≤480 — секции стопкой друг под
другом; `tab:` от 481; `desk:` от 1200 (`--breakpoint-*` в
`app/globals.css`). Приёмка — 375 / 768 / 1440 плюс граничные 480↔481 и
1199↔1200.

Планшетный ярус (481–1199): все секционные H2 — 32/36 Onest SemiBold
(`tab:text-[32px] tab:leading-9`; решение по кадру 3005-78023, 05.10).
Герой — исключение: Landing/H3 36/40 Medium. Заголовки карточек сидят на
своих размерах макета (22/26, 28/32, 16/20) и без кадра не трогаются.

## 3. Полосы и карусели

Канон взаимодействия (референс — карусель Яндекса, секция «Опыт наших
партнёров», замер 02.10, viewport 1440): автоплея нет; жёсткий край с
резиновой оттяжкой; карточки плоские (без scale/затемнения); drag 1:1,
отпуск = снап 360ms CSS `ease` независимо от дистанции, скорость броска
учитывается; Shift+Scroll — 1 событие = ровно 1 шаг, события во время
анимации глотаются (не в очередь); вертикальное колесо скроллит страницу;
клик или захват мыши в полёте перебивает переход; клик по карточке ничего
не делает; контейнер — контент-колонка с `overflow:visible` (карточки текут
за колонку до обреза вьюпортом).

Четыре секции-полосы (финансы, дела, аудитория, тарифы): на `desk:` —
статичные ряды (движок отключён); на `tab:` — перетаскивание
(`components/tablet-strip.tsx` + `components/strip-engine.ts`); на мобайле —
стопка.

Механика strip-engine (грабли приёмки, каждое оплачено красным ассертом):
цели скролла — только из SNAP-модели (живые offsetLeft врут при морфинге);
копии ленты шагают на N слайдов, INITIAL средней копии = N+2; ширина модели
— `clientWidth` скроллера (full-bleed), не колонки; normalize копий — сдвиг
на copyPlain; магнит settle ставит точный SNAP по scrollend; мутабельное
состояние — `useRef` с ленивой инициализацией в эффекте.

Showcase («Создайте карточку своей недвижимости») — не strip-engine:
два ядра Swiper, связанных штатным модулем Controller (решение владельца
26.10 после лагов версии 24–25.10 с самописным морфом `--k` на
setTranslate: перерасчёт k и запись стилей на каждый pointermove
соревновались с композитором; теперь всё движение библиотечное —
сама механика на эффекте `coverflow`, как у референса, блока
«Опыт партнёров» на yandex.ru/id/business, живой замер 26.10: Swiper
speed 600, coverflow rotate 0 / scale 0.5 / stretch / depth, Mousewheel
forceToAxis, автоплей сконфигурирован, но не запущен). Канон блока:

- Тайминг — плоский CSS `ease` @ 600ms (замер 26.10: computed
  `transition-timing-function` обёртки Яндекса в полёте = `ease`, ни
  одного правила с кривой в их стилях; подгонка по 60 кадрам — RMS 0.070
  для ease против 0.164 у `cubic-bezier(0.33, 1, 0.68, 1)` из «замера
  24.10» — тот замер живой анимацией не подтвердился, кривая снята).
  Кривая и свойство перехода слайдов — в `--showcase-ease` модуля
  секции; coverflow пишет слайдам только инлайн transform и
  transition-duration, в полёте интерполирует композитор.
- Морф боковых — штатный `coverflowEffect` (rotate 0, depth 0, scale
  0.8, slideShadows false, `stretch = 0.1·ширины − зазор макета`,
  spaceBetween 0, слайды в слотах полной ширины): формула ядра
  `scale = 1 − (1−0.8)·|дистанция|` даёт соседа ровно 0.8 с зазором
  макета (та же геометрия покоя, что в слотах 0.9·ширины + gap), ни
  одного layout-свойства в кадре. Линейность без «пола»: дальний план
  0.6 — на всех ярусах за клипом/шторкой (проверено геометрией),
  решение владельца 26.10; на ультрашироких (>~3000px) под шторкой
  виден осколок дальнего фото — осознанное отклонение.
- Фотолента и ряд плашек — два `Swiper`, Controller `by: 'slide'` в
  обе стороны: сплайн snapGrid→snapGrid на равномерных сетках копий —
  точный аффинный маппинг, контроллер ведёт ведомую (translate,
  индексы, классы, transitionEnd). Драг любой ленты — нативный
  (drag 1:1, флик, снап, резинка — release-механика ядра); порог
  переброса — полшага, недотянутая тяга релизится как тап по видимой
  плашке/карточке (slideToClickedSlide) — канон «клик по боковой
  приводит её к центру».
- Бесконечность — 3 копии набора с тихой пересадкой `slideTo(±N, 0)`
  обеих лент на покое (единственный не-библиотечный ход, невидимый:
  0мс по обеим лентам, только из состояния покоя). Нативный
  `loop: true` невозможен и на Swiper 14.3.0 — воспроизведено приёмкой
  26.10: петля переставляет DOM-слайды каждой ленты независимо (у лент
  разные шаги и контейнеры → разные buffers loopFix), Controller
  сопоставляет ленты позициями сеток и перестановки не передаёт —
  пары «фото↔плашка» перекрещиваются сразу после инициализации
  (photos realIndex 2 при plates realIndex 0). Замер 24.10 и запрет —
  подтверждены; не возвращать без апстрим-фикса контроллера.
- Колесо — модуль Mousewheel (`forceToAxis`, `eventsTarget` на зону
  секции): горизонтальный трекпад и Shift+колесо листают, вертикальное
  колесо скроллит страницу; события в полёте ядро глотает (guard
  `!animating`), серия даёт шаг каждые ~600ms — как у референса.
- Клик-в-центр — `slideToClickedSlide` (только tap: клик после драга
  ядро гасит сам); клавиатура — Enter/Space по фокусу: слайд через
  onKeyDown, плашка-кнопка — через onKeyDown c preventDefault
  (нативный клик кнопки не проходит через tap-путь ядра).
- Автоплея и стрелок клавиатуры нет (решение владельца 24.10;
  у референса автоплей в параметрах, но не запущен — совпадает).
- Ярусы — по ширине окна (CSS-медиазапросы модуля); на смене яруса
  пересчитывается только `coverflowEffect.stretch` (breakpoints
  Swiper'а меряют контейнер, а плашечный уже окна).
- Грабли ядра при приёмке 26.10 (каждое рвало ленту, лечатся
  параметрами и одним запретом): релиз медленного (дольше 300ms)
  драга без `longSwipes: true` всегда идёт в `slideTo(activeIndex)` —
  порога половины шага не существует, боковая плашка при медленной
  тяге всегда откатывала; дефолтный `lazyPreload: true` на каждый
  догруз картинки внутри контейнера зовёт `update()` со мгновенным
  `slideTo(*, 0)` — телепорт под пальцем (картинки секции грузятся
  eagerly, слушатель снят); захват ленты во время 600ms-перехода рвёт
  её на кадр — ядро на первом move гасит CSS-переход, и тот вспыхивает
  целевой позицией полёта, поэтому переход гасится в `touchStart`
  синхронным переносом JS-позиции в визуальную
  (`setTranslate(getTranslate())` — паттерн freeMode ядра), а
  пересадка копий запрещена, пока пальцы на лентах или переходы в
  полёте (синтетический `transitionend` несёт ещё целевой translate —
  пересадка по нему телепортировала ленту из-под пальца). Релиз —
  всегда по ближайшему снапу: `longSwipesMs: 1` переводит любой
  релиз в ratio-ветку ядра (решение владельца 26.10): без него
  дефолтная shortSwipes-ветка считает prev по границе интервала
  сетки, и быстрая перетаскашка боковой плашки ровно на шаг улетала
  на шаг дальше (забран и флик-бонус коротких бросков — перелист
  остался за колесом, кликами по боковым и дотягиванием за полшага).
  window-resize во время удержания ленты ядром тоже телепортировал
  (репро 26.10: лента мечется под удержанным пальцем): update()
  ведомой фотоленты делает slideTo(activeIndex, 0) без метки
  byController, и кольцо контроллеров ответным телепортом дёргает
  мастеровые плашки — updateOnWindowResize выключен, геометрию на
  ресайзе обновляет свой хендлер: сразу на покое и отложенно до
  первой остановки, если лента в руках (плюс таймер в touchEnd для
  релиза без полёта).
- Грабли iOS-композитора при приёмке 27.10: Safari и Chrome на айфоне
  (оба — WebKit) при драге роняют бесслойных соседей стекла с
  backdrop-filter — текст плашки исчезал под пальцем; рамка
  (`.cardRing`) падала тем же способом даже без блюра. Лечение —
  собственные композитные слои: `translateZ(0)` на текст и рамку в
  модуле секции (нулевая плоскость в 3D-контексте слайда, вида не
  меняет; слой на родителе `.card`, снятие `preserve-3d` и
  `perspective` не помогают — проверено переключателями на живом
  айфоне). Не снимать.
- Грабли ядра 27.10, «секции проскакивают» при драге плашек: mousedown
  фокусирует кнопку плашки, и первый pointermove по её поверхности
  (пэддинги, зоны между иконкой/текстом/стрелкой) глотался guard'ом
  ядра (`e.target === document.activeElement` и матчится
  `focusableElements`) — жест помечался `isMoved` до чтения
  `startTranslate`, и следующий move считал позицию от хвоста
  `touchEventsData` прошлой тяги: лента телепортировала на разницу
  одним кадром (замер 27.10: −2875 → −552 за кадр; фотолента — следом
  через контроллер). Телепорт плавающий: скачок равен хвост минус
  живая позиция — ноль после драга на том же месте, сотни px после
  пересадки копий, клика или колеса. Лечение — `focusableElements:
  'input, select, textarea'` в обеих лентах: guard перестаёт глотать
  драг по кнопкам (у div-слайдов фотоленты `role="button"` с
  `'button'` не матчится — там баги не было; сужение там — на
  упрочнение). Развод тапа и драга у ядра свой (allowClick +
  slideToClickedSlide) и от списка не зависит; `:active`, тап по
  боковой, Enter/Space, Shift+колесо проверены живой приёмкой на
  1440 и 375.

Steps («Как начать пользоваться») — тоже Swiper, не strip-engine
(решение владельца 26.10 — полная копия механики эталона
pay.yandex.ru/business/payments/qr «Как подключить QR-код к вашему
бизнесу», живой замер 26.10): один инстанс, эффект fade cross-fade —
слайд «текст шага + мокап» целиком кроссфейдится на месте, opacity
следует за жестом (`watchSlidesProgress`); свайп и мышиный драг по
всей зоне карусели (simulateTouch, grabCursor выключен — как в
эталоне); петли нет — за краем сопротивление и возврат ядра;
автоплея нет (в конфиге эталона автоплей прописан, но фактически не
стартует — листается только руками; решение владельца 26.10);
клавиатурных стрелок нет. Скорости эталона — 360мс при окне ≥720 и
460мс при <720; граница живёт на ширине окна (breakpoints ядра меряют
контейнер — скорость ставится вручную по matchMedia), кривая —
дефолт ядра CSS ease. Кнопки шагов — вне карусели, как буллеты
пагинации эталона: клик → slideTo, активная по slideChange. Текстовая
зона слайда — min-h на две строки на мобиле и одну на планшете-десктопе
(40/20px, решение владельца 26.10): fade-слайды лежат стопкой в точке
активного, без равной высоты мокапы прыгали бы по вертикали при
кроссфейде (у эталона слайды тоже равной высоты — inline height
534px, замер). Режим out-in с ужатыми таймингами (300/380,
ease-in/out) испробован и откачен решением владельца 26.10 («стало
хуже» — окно пустоты на середине читается пульсом на светлой панели;
полный дамп эталона подтверждает cross-fade 360/460 ease) — не
возвращать без нового решения; View Transition API также отклонён:
для смены на месте это тот же кроссфейд снимками плюс цена захвата,
за пальцем не следует.

Rentals («Управляйте арендой») — Swiper, не strip-engine (решение
владельца 26.10 — полная копия механики эталона
pay.yandex.ru/business/checkout, блок «Чекаут Яндекс Пэй открывает
возможности экосистемы Яндекса», живой дамп конфига и поведения
Swiper 26.10): один инстанс, `slidesPerView: 'auto'`, петли нет — за
краем сопротивление ядра (0.85) и возврат; drag 1:1 (simulateTouch,
grabCursor выключен — курсора «руки» нет, как в эталоне), threshold 5,
отпуск — снап к ближайшей позиции; клик по карточке ничего не делает.
Скорости эталона — 360мс при окне ≥720 и 460мс при <720, кривая —
дефолт ядра CSS ease; граница и уровни breakpoints живут на ширине
окна (`breakpointsBase: 'window'` — дефолт ядра и эталона). Окно <720 —
`centeredSlides` + `centeredSlidesBounds`: активная карточка по центру
с подглядывающими краями соседей, первая прижата к левому краю,
последняя — к правому; ≥720 — карточка у левого края колонки.
Уровни breakpoints ядра НЕ каскадят: выбирается один — старший
совпавший, и он extend'ится поверх params (исходники setBreakpoint) —
каждый уровень повторяет полный набор параметров. Колесо — модуль
Mousewheel (`forceToAxis`, eventsTarget — контейнер, как в эталоне):
Shift+колесо и горизонтальный трекпад листают, вертикальное —
страница; вертикальный пан на таче — страница (`touch-action: pan-y`
в core-CSS). Автоплея нет (в конфиге эталона autoplay delay 3000
прописан, но фактически не стартует — живой замер 26.10; решение
владельца 26.10), буллетов пагинации и стрелок нет (решение владельца
26.10: макеты 2967-75818 точек не имеют, пагинация эталона на секцию
не переносится). Метки слайдов «N / M» — модуль A11y с дефолтами
ядра, как в эталоне (в core-сборке модуль не включён по умолчанию).
Контейнер `.swiper` — `overflow: visible` поверх
core-hidden (карточки текут за колонку до обреза секционным
`overflow: clip`), user-select выключен на зоне карусели. Гэп —
наш макетный `spaceBetween` (12/20px на границе окна 1200), у эталона
его роль играют паддинги слайдов. strip-engine из секции снят; сам
движок остаётся в testimonials и tablet-strip.

overflow-канон: «клип без скролла» — только `overflow:clip`; `hidden`
оставляет бокс скролл-контейнером, и WebKit прокручивает его жестом.
Трансформированные потомки дают scrollable overflow — viewport движка
держит `hidden`+`clip`; нативные
полосы — утилита `strip-scroll` (`app/globals.css`): `overflow-x:auto` +
`contain` только на 481–1199, на `desk:` ряд статичен и контейнер не нужен.

## 4. Фото: конвейер и лестница

Исходники — оригинальные байты imageRef-заливок Figma → webp q100 (sharp);
выдача AVIF `qualities: [90]` (решение владельца 16.10, #1500 — вместо 95:
вес фото ~вдвое меньше при визуально неотличимой выдаче, откат при видимых
артефактах на живой приёмке; пропы держать синхронно с конфигом — большее
значение молча прижимается к ближайшему разрешённому). Лестница
размеров — дефолтная Next (браузер берёт минимальную ступень
≥ ширины экрана × DPR); кастомная лестница снята решением владельца
24.10 — srcset-URL меняются, после деплоя прогрев `warm-images.mjs`.
Оптимизатор зажимает по
intrinsic: ступени выше intrinsic-ширины источника дают те же байты
(апскейла нет). Провенанс — `ATTRIBUTIONS.md`.

`<picture>`: `loading="eager"` + `fetchPriority="high"` — канон;
`placeholder="blur"` с `getImageProps` несовместим. Ассеты писать атомарно:
не-атомарная замена под живым dev-сервером ловит «unable to decode image
data» до рестарта.

Прогрев и переживание кэша оптимизатора (практики Эмиля Ковальски, 14.10):
кэш `/_next/image` дисковый (`.next/cache/images`), деплой-компоуз монтирует
именованный volume `landing-image-cache` на `/app/.next/cache` (каталог
создан в Dockerfile с владельцем nextjs — volume на пустом пути достался бы
root) — тёплый кэш переживает замену образа. Холодный старт нового набора
картинок догревает `node apps/landing/scripts/warm-images.mjs <baseUrl>`:
собирает все варианты `/_next/image?…` из src/srcset трёх страниц (лестница
уже перечислена в разметке) и GET-ит их с AVIF-Accept; выход 1 при неудачах.
Грев строго последовательный, с паузами и бэкофф-ретраями на HTTP-ошибки
(решение владельца 15.10, прогон стейджа: 8 параллельных холодных 4k-кодирований
валили контейнер — Caddy массово 502 при 18/134; одиночные запросы апстрим
держит спокойно). Запуск — вручную после каждого деплоя лендинга (решение
владельца 16.10, #1502 — шага воркфлоу нет); смена лестницы или качества
делает все URL в разметке новыми (research #1503) — греть сразу после
вливания, инвалидация кеша при расширении лестницы не нужна (allowlist-надмножество,
старые URL остаются валидными).

## 5. Стенд и пересборка

`next start`/`next build` — строго из `apps/landing` активного чекаута;
порт берётся из `.env` слота (в свежем ворктри сначала `npm ci` в
`apps/landing`), не хардкодится. Standalone-лейаут FLAT: после сборки
копировать `.next/static` → `.next/standalone/.next/` и `public` →
`.next/standalone/`, затем рестарт `node server.js` — работающий сервер
продолжает отдавать 404, пока не перезапущен. Симптомы: 404 на
`/fonts/*.woff2` — не скопирован `public`; 400 «isn't a valid image» от
`/_next/image` — не скопирован `static`. `npm exec` съедает `-p` — бинарь
пускать напрямую: `./node_modules/.bin/next dev -p PORT`.

## 6. Приёмка и Figma

Скрины вьюпортные или full-page: ограничение «только вьюпортные» ушло
вместе со scroll-reveal (снят 24.10 — full-page больше не оставляет
секции пустыми). Playwright `mouse.wheel` шлёт событие в позицию курсора — перед
wheel двигать курсор на ленту, иначе шагает страница. Селектор
`[class*="track"]` не матчит `stripTrack` (регистр); `m41` матрицы = −p
(следить за направлениями в ассертах); резинку за край тестировать с края
диапазона.

Figma: `get_design_context` на больших узлах упирается в 30-секундный
таймаут — дробить узел или брать `get_metadata` (размеры и стили текстов
без тяжёлой выгрузки) + `get_screenshot`. Роли серверов — `docs/agents/mcp.md`.

  и шапки формы «Свяжитесь с нами» — осознанное отклонение канона

  осознанное отклонение от канона шелла выше (решение дизайнера по кадрам
  3350-160996/3406-78074/3406-78168: контент короткий, скроллить и тянуть
  нечего). Править перенос = drift, поэтому исключение живёт здесь.

Скролл-лок: Radix/vaul ставит `body[data-scroll-locked]` и превращает body
в скролл-контейнер при базовом `overflow-x: clip` — sticky-хедер срывается.
Канон фикса — unlayered-правило, побеждающее библиотечный слой:
`html body[data-scroll-locked] { overflow: clip !important; margin-right:
0 !important; padding-right: 0 !important; }` (`app/globals.css`). Хедер при
открытом оверлее скрыт за ним по дизайну (z-50) — не поднимать выше
(решение владельца).

## 8. Мобильно-платформенный слой

Практики Эмиля Ковальски (mobile-native), применённые 14.10:

- `html { -webkit-tap-highlight-color: transparent }` — серая вспышка тапа
  спорит с собственным press-фидбеком кнопок (`:active`, доска 2864-5099);
  hover-стили Tailwind v4 уже гейтятся `(hover: hover)` — на тачах нажатие
  отвечает только `:active`.
- `:root { color-scheme: light }` — лендинг только светлый; без явного
  значения тёмная ОС рендерит UA-виджеты (скроллбары, автозаполнение) тёмными.
- Известный долг (вне зоны лендинга): плавающая метка `text-field` анимирует
  `top`/`font-size` — layout-анимация; компонент портативный, правится
  только синхронно с фронта явным решением. Половина долга погашена 14.10
  (аудит анимаций): `transition-all` сужен до точного списка свойств
  (`transition-[top,font-size,line-height]`); перевод метки на transform —
  за фронтом.
- Поддержка `prefers-reduced-motion` снята с лендинга ЦЕЛИКОМ (решение
  владельца 14.10 после живого теста: анимации должны работать у всех —
  reduce-ветки глушали их тем, у кого в ОС включено «уменьшить движение»,
  в том числе аккордеон FAQ). matchMedia-проверки, классы `motion-reduce:*`
  и reduce-блоки `globals.css` вырезаны. `prefers-reduced-transparency` и
  `prefers-contrast` остаются — это независимые сигналы. Без явного нового
  решения владельца не возвращать.
- Токены кривых моушена: `--ease-enter` (въезды; после снятия
  scroll-reveal 24.10 без потребителей, оставлен в семействе), `--ease-inout`
  (симметричные подмены тарифов; до 26.10 подменял и steps — секция
  переведена на fade-Swiper с дефолтным ease ядра, §3; анимация
  `--animate-steps-text-in` с тех же пор без потребителей, keyframes
  живы за тарифным токеном), `--ease-menu` (морф бургера мобильного
  меню — возвращён решением владельца 27.10; между переносом меню
  в карточку хедера 24.10 и возвратом был без потребителей), `--ease-desk` (десктопные переходы отзывов) в `@theme` —
  утилиты `ease-*`; значения замерные, сведение в токены их не меняло.
  Кривая strip-движка и отзывов — `components/carousel-ease.ts`; кривая
  showcase — плоский CSS `ease` (живой замер «Опыт партнёров» 26.10,
