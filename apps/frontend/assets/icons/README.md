# Иконки PWA: набор и процесс обновления

Внешних генераторов в процессе больше нет (решение владельца 27.10.2026,
после бага «старая иконка при установке»; RFG-процесс тикета #781 снесён):
все арты — мастера владельца из Figma, производные собираются локально
скриптами репо. Владелец приносит только арты; механика (ресайз, ICO,
сплэши, копии лендинга) — на агенте.

| `public/icons/splash/*.png` (28, iOS-сплэши) | дом на белом #ffffff | `icon-512.png` | `npm run generate:splash` |
| лендинг `apps/landing/app/{favicon.ico,icon.png,apple-icon.png}` | как кабинетские | байт-копии кабинетских | агент (`cp`) |

Нюанс лендинга: в проде Caddy (`deploy/caddy/rentlee.caddy`, матчер
`@landing`) отдаёт `/icon.png`, `/apple-icon.png`, `/favicon.ico` из
лендинга — кабинетские file-convention по этим путям затенены. Копии
обязаны быть байт-идентичными кабинетским, иначе прод показывает не тот
арт (карта #1610, находка research #1612).

## Правило версий: смена арта = смена URL

`/icons/*` раздаётся с `Cache-Control: public, max-age=31536000, immutable`
(`next.config.ts`, решение владельца 22.10.2026). Смена содержимого под тем
же URL для кэшей не существует: браузер и WebAPK держат старые байты,
переустановка PWA не помогает — HTTP-кэш Chrome удалением приложения не
чистится. Баг 26–27.10: maskable заменили в репо, прод уже отдавал новые
байты (md5-сверка), а на устройстве после переустановки оставалась старая
иконка.

Поэтому любая замена арта — бамп `?v=ГГГГММДД` во всех потребителях URL:

- `app/manifest.ts` — манифестные иконки (4 src);
- `shared/lib/pwa/push-payload.ts` — push-иконка;
- `public/sw.js` — её inline-копия.

Guard-тест: `shared/lib/pwa/icon-urls.test.ts` — валит URL без `?v=` и
расхождение версий между тремя файлами. Файлы в `public/icons/` при бампе
не переименовываются и не трогаются: меняется только строка запроса у
потребителя.

## Порядок обновления набора

1. Владелец: новый арт в Figma-мастера; экспорт apple-touch 180×180
   (непрозрачный полный квадрат, узел 2353:52637); maskable-мастер — у
   дизайнера (1024, арт в круге 0.63).
2. Агент: положить мастера в `assets/icons/` → `npm run generate:icons` →
   `npm run generate:splash` → скопировать `favicon.ico`/`icon.png`/
   `apple-icon.png` в `apps/landing/app/` → бамп `?v=` в трёх потребителях
   (см. правило версий).
3. `npm test` (guard icon-urls), глазом сверить 192/512 с мастером.
4. Пуш и деплой, затем на устройстве: удалить PWA → установить заново —
   установка читает манифест по новому URL и гарантированно берёт новые
   байты. Уже установленные без переустановки догоняют через WebAPK-update
   Chrome по его расписанию; форс — `about://webapks` → Update.

## Проверка иконки в Dock (macOS)

Какая иконка куда попадает: Dock-приложение, ставимое Chrome, берёт
манифестные `any` 192/512 (наши прозрачные вписанные); «Добавить в Dock»
в Safari — `app/apple-icon.png`; таб браузера — `favicon.ico`/`app/icon.png`;
Android-лончер — `icon-maskable-512.png`.

Иконка Dock кэшируется macOS (LaunchServices/Dock): установка поверх старой
может показывать прежнюю иконку даже после переустановки. Грабля 21.09
(выглядело как регресс набора «иконка снова обрезается»): в Dock оставалась
старая дофиттинговая иконка из кэша. Перед проверкой новой иконки: закрыть
браузер, снести ВСЕ установленные копии PWA (в т.ч. прежние версии в
`~/Applications/Chrome Apps`), поставить заново — только тогда Dock прочтёт
свежий icns.
