# Иконки PWA: процесс обновления (RealFaviconGenerator)

Генераторов в репо больше нет — набор иконок собирается внешним сервисом
[RealFaviconGenerator](https://realfavicongenerator.net) (решение владельца
21.09.2026, тикет #781). Владелец прогоняет мастер через сайт и приносит
результат, агент раскладывает файлы по репо.

## Мастера

| Файл | Что это |
|---|---|
| `source-icon.svg` | скруглённый мастер из Figma («Рентли. Новые экраны сервиса», узел 2358:139864) — дом #2B7FFF, дверной путь white, фон #BCDCFF с прозрачными углами |
| `source-square.svg` | тот же арт полным квадратом (Figma 2353:52637) — эталон-источник для сверки maskable/apple-touch с полным артом и мастер непрозрачных поверхностей на случай ручного прогона; в RFG не загружается |
| `source-icon-fitted.png` | референс вписанного арта: дом вписан в 74% холста и отцентрован (решение владельца от 21.09: macOS 26 маскирует иконки Dock в системный сквиркл — полный арт режется); **его загружают в RFG** — прозрачный PNG, вход фактического прогона 21.09 |
| `source-maskable-android.png` | Android-maskable от дизайнера (26.10, карта #1610): дом по центру (макс. радиус 0.63 < safe zone 0.8), дорожка завершается внутри холста, фон полным квадратом с прозрачными скруглёнными углами и белым глоу-кантом. Из него собирается `public/icons/icon-maskable-512.png` (даунскейл 1024→512). Вид владельцем на устройстве (WebAPK через tuna-туннель) одобрен 26.10; компоновка с дорогой «до края» прежнего maskable не дожила до прода — лончеры её резали |
| `source-monochrome.svg` | силуэт дома для Android 13+ themed-иконок (механизм monochrome, RFG его не делает) |

## Как обновить набор

1. Загрузить на realfavicongenerator.net прозрачный `source-icon-fitted.png`
   — фактический прогон 21.09 сделан именно им. RFG из прозрачного входа
   сам красит альфу на непрозрачных поверхностях: тот же прогон дал полные
   квадраты apple-touch и maskable, поэтому отдельный вход из
   `source-square.svg` не нужен.
2. Настройки платформ — секции по умолчанию, кроме iOS: отступы вписывают
   дом до ~74% ширины (ориентир — `source-icon-fitted.png`; macOS 26
   маскирует иконки Dock в сквиркл — полный арт режется, грабля кэша Dock
   описана ниже, в разделе «Проверка иконки в Dock (macOS)»);
   - **Desktop**: по умолчанию (ICO + PNG) — при fitted-входе это честно:
     прозрачные скруглённые углы таб-пары (`favicon.ico`, `app/icon.png`)
     наследуются от мастера (канон `docs/research/pwa-icons-canon.md`,
     строка «Таб браузера» матрицы прозрачности);
   - **Windows tiles и Safari pinned tab (mask-icon): выключить** — мёртвые
     механизмы, research `docs/research/pwa-icons-canon.md` их запрещает;
   - их `site.webmanifest` и HTML-сниппет **не брать** — манифест у нас свой
     (`app/manifest.ts`), линковку делает Next.js file conventions.
3. Скачать зип и передать агенту.

Пометка о прогоне: конфигурацию сессии RFG (поля формы на сайте) знает
только владелец — фактический прогон 21.09 делал он. Если следующий
реальный прогон даст расхождение с бинарниками в репо, README правится
по слову владельца — расхождение вскроется на том же прогоне.

## Куда что кладёт агент (маппинг, Next.js-набор RFG от 21.09)

| Файл из RFG | Куда в репо |
|---|---|
| `favicon.ico` (16/32/48) | `app/favicon.ico` |
| `apple-icon.png` (180, непрозрачный) | `app/apple-icon.png` |
| `icon1.png` (96, прозрачный) | `app/icon.png` |
| `web-app-manifest-512x512.png` | некуда с 26.10: maskable собирается из `source-maskable-android.png` (карта #1610), RFG-вариант не берётся |
| `web-app-manifest-192x192.png` | некуда: в манифесте нет 192-maskable записи — не брать |
| `icon0.svg` (SVG-favicon), `manifest.json` («MyWebSite»), прочее | **не брать** — SVG-favicon — опциональное дополнение research (§6, №7), решено не брать; манифест свой (`app/manifest.ts`) |

Нюанс: RFG в Next.js-наборе отдаёт `web-app-manifest-*` как **непрозрачные
квадраты (purpose maskable)** — они идут только в maskable. Purpose `any`
(`public/icons/icon-192.png`, `icon-512.png` — прозрачные, дом вписан 74%)
RFG не делает: эти два файла в репо постоянные, пока RFG не начнёт отдавать
прозрачный вариант.

Отклонение maskable (исчерпано 26.10): прежний `icon-maskable-512.png` от
прогона RFG 21.09 держал дом на радиусе ~0.79, а белый низ дороги выводил
арт за safe zone 80% до ~1.0 — Android-лончеры с круглой маской резали
дорожку, иконка выглядела «крупной» (жалоба владельца, карта #1610).
Замещён композицией дизайнера `source-maskable-android.png`: дом в круге
0.63, дорога завершается внутри холста; замер и превью под круглую/сквиркл
маски — в resolution карты #1610 (тикет #1612 и сессия 26.10).

`public/icons/icon-monochrome-512.png` RFG не делает — файл в репо, обновляется
только вместе с `source-monochrome.svg`.

## Проверка иконки в Dock (macOS)

Какая иконка куда попадает: Dock-приложение, ставимое Chrome, берёт
манифестные `any` 192/512 (наши прозрачные вписанные); «Добавить в Dock»
в Safari — `app/apple-icon.png`; таб браузера — `favicon.ico`/`app/icon.png`;
Android-лончер — `icon-maskable-512.png`.

Иконка Dock кэшируется macOS (LaunchServices/Dock): установка поверх старой
может показывать прежнюю иконку даже после переустановки. Грабля 21.09
(выглядело как регресс набора «иконка снова обрезается»): в Dock оставалась
старая дофиттинговая иконка из кэша. Перед проверкой новой иконки: закрыть
браузер, снести ВСЕ установленные копии PWA (в т.ч. прежние версии в
`~/Applications/Chrome Apps`), поставить заново — только тогда Dock прочтёт
свежий icns.
