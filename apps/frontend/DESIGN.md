# DESIGN.md — дизайн-конвенции фронтенда

Как строить UI новых экранов, чтобы всё выглядело и вело себя одинаково. Читать
перед любой UI-работой; визуальные решения поверх этого файла принимает только
владелец. Пара к этому файлу — **витрина `/ui-kit`**: живые примеры всех
компонентов дизайн-слоя; новый/изменённый компонент попадает на витрину в том
же коммите (см. «Фиксация решений»).

Первоисточники: макеты Figma («Рентли. Новые экраны сервиса»), токены
`shared/styles/tokens.css` (проброс через `@theme inline` в `app/globals.css`),
дизайн-слой `shared/ui/design/` (ADR 0050: shadcn/ui-паттерн поверх
Radix-примитивов + vaul), шрифт Onest.

## 1. Ширины и брейкпоинты

- Мобильный макет — 393px; ширины 561–768 — колонка контента по центру, не
  тянем во всю ширину; десктоп — та же колонка 560 внутри «крыльев» TopNav.
- Мобайл ≤768, десктоп ≥769 (брейкпоинт `--breakpoint-desktop`). В коде —
  Tailwind-префикс `desktop:`; в JS — `useIsDesktop()` из `shared/ui/design`
  (SSR-дефолт true, корректируется после гидратации — модалки открываются
  только по действию пользователя, к тому времени ветвление скорректировано).
- Единственная колонка контента — `max-w-[560px]` по центру на любой ширине.

## 2. Хедер и TabBar

- `<TopNav>` — единый хедер, экран не строит свой `<header>` и не двигает
  хедер. `leading` — выход из экрана (`ArrowLeft` «Назад» или `Cancel`
  «Закрыть»), дети — `<TopNavTitle>` (заголовок 16/18, опциональный
  подзаголовок), `trailing` — действия. Вариант `search` — поисковая шапка
  (лупа открывает, назад закрывает, поле получает программный фокус).
- Мобайл: полоса в потоке, 72px + `safe-area-inset-top`, во всю ширину.
  Десктоп: закреплена над прокруткой, центральная колонка max-560, по краям
  «крылья» — лого «Рентли» и кнопка профиля (приносит `TopNavUserContext`).
- `<TabBar>` глушится автоматически, пока смонтированы StickyBottomBar или
  полновысотный экран со своей нижней панелью.

## 3. Страница

- `<PageContent>` — единственная колонка контента: max-560 по центру, `pt-6`,
  снизу `pb-[136px]` под нижнюю панель. Строки списков приносят свой
  горизонтальный паддинг (24px), остальное оборачивает экран.
- `<StickyBottomBar>` — закреплённая нижняя панель действия (кнопка экрана,
  справа — как в формах задач). Если панель видна не всегда — TabBar
  возвращается сам при её исчезновении.
- **Полновысотные экраны с внутренней прокруткой** (календарь, длинный список
  под закреплённой шапкой) не строят собственный `h-dvh`-каркас: PageContent
  получает `className="flex h-[calc(100dvh-72px)] flex-col pb-0"`, закреплённые
  блоки — `shrink-0`, прокручиваемая область — `flex-1 min-h-0 overflow-y-auto`
  с внутренним нижним паддингом под панель (прецедент: пикер даты).

## 4. Поверхности — что выбрать

| Поверхность | Когда | Пример |
|---|---|---|
| **Страница-маршрут** (`router.push`) | полноэкранные формы, детали, флоу; «полноэкранный шит» = страница-маршрут | создание/правка задачи, детали платежа |
| **Полноэкранный оверлей** (`fixed inset-0` + `role="dialog"`, рендер только в открытом состоянии) | временный пикер поверх формы — состояние формы не теряется | `CalendarDatePicker` |
| **`Modal`** — карточка ≥768 / vaul-шит <768 | короткие выборы и подтверждения из формы; в шите — drag-ручка, закрытие свайпом/оверлеем | время задачи, подтверждения |
| **`PickerMenu`** — меню на десктопе / шит на мобиле | выбор одной опции из групп («радио»), триггер-кнопка | сортировка задач и контактов |
| **`Menu`** (Radix dropdown) | контекстные действия без семантики выбора | «действия со списком» задач |

Переходы между экранами: завершение потока — `goBack(router, fallback)`,
создание сущности — `router.replace` на новую страницу, вход в поток —
`router.push` (подробно — «Navigation» в CODING_STANDARDS).

## 5. Пикеры и колёса

- **`CalendarDatePicker`** — выбор даты: полноэкранный оверлей, sticky-шапка
  (TopNav + чип «Месяц Год ⌄» + строка дней недели над прокруткой), лента
  месяцев бесконечно вперёд (дорисовка годом у края + `content-visibility`
  на блоках), старт от самого раннего из «сегодня» и значения (якорь правки
  #502). Дата опциональна: повторный тап снимает выбор, «Выбрать» коммитит.
- **`WheelPickerSheet`** — универсальный шит колёс: любое число колонок
  (`<WheelPicker/>` без своего flex-класса, `strip={false}`) + передаваемые
  кнопки (`label`/`variant`/`onSelect`; одна — во всю ширину, две — пополам).
  Заголовок sr-only, полоса выбора одна на все колонки со скруглением только
  внешних краёв.
- **`MonthYearPicker`** — шит месяц/год на WheelPickerSheet: проп `min`
  закрывает прошлое (годы ниже min.year отсутствуют, в году min — месяцы
  ниже min.month0), годы расширяются вперёд бесконечно (`onNearEnd` колеса
  удлиняет список на 10 лет у края). Рендерить только в открытом состоянии —
  черновик колёс живёт, пока шит смонтирован.
- **`WheelPicker`** — окно 240px = 5 рядов ×48px (по 2 над и под выбранным,
  поля 96px), кегль всех рядов единый 20/24 (различие только цветом:
  выбранный `text-content`, остальные `text-content-secondary`), коммит
  значения после settle скролла; клик по ряду и клавиатура коммитят сразу.
  Полоса в самом колесе — только для одиночного использования; в шите её
  рисует контейнер.
- **`PickerMenu`** — группы опций-«радио» (см. таблицу поверхностей); опция:
  `{ label, selected, onSelect }`, выбор применяется сразу. Триггер-кнопка
  обязана прокидывать `…props` (asChild триггера передаёт обработчики/aria).
- **`MonthDaysGrid`** — мультивыбор дней месяца + «последний день месяца».
- **`CalendarMonth`** — одиночный блок месяца без ленты (визард платежей).

## 6. Состояния списков

- Loading → скелетон экрана; error → карточка с retry; empty → EmptyState
  (иллюстрация + текст + действие). Внешний вид — по макетам фич, общие
  примитивы скелетона и EmptyState — в бэклоге унификации: до их появления
  локальные реализации допустимы, новые не плодить без причины.
- Пустой список прячет служебные чипы (сортировка/фильтры) вместе с собой.

## 7. Motion, hover, focus

- Единая кривая `cubic-bezier(0.32, 0.72, 0, 1)` (`--dl-ease`): 250ms
  (`--dl-duration-fast`) цвета/фоны/границы, 350ms (`--dl-duration-move`)
  движение/трансформы, 300ms floating label TextField. Tailwind берёт дефолты
  из `@theme`; в CSS Modules — переменные явно. Жёсткие `Ns ease` запрещены.
  `prefers-reduced-motion` не гейтится (решение владельца).
- Touch-safe hover: Tailwind `hover:` уже эмитится внутри
  `@media (hover: hover)`; в CSS Modules каждое `:hover` — внутри media-блока.
- Focus: полям ввода кольцо не положено (caret — аффорданс); кнопки и ссылки
  держат `:focus-visible` ring.

## 8. Даты и деньги

- Даты — только `shared/lib/calendar` (ISO-математика: `fromIso`, `addDays`,
  `daysOverdue`, месяцы, лента пикера) и `shared/lib/date-format` («11 августа»,
  «13 мая, 2027», «N дней» через `pluralize`). Ручные `slice`-парсинг, Intl и
  склонения на местах запрещены. «Сегодня» — параметром от сервера (ADR 0048),
  клиент часов не держит; всё в UTC.
- Деньги — integer kopecks, только `shared/lib/format-money.ts`
  (`formatMoneyKopecks` / `kopecksToRublesString` / `parseRublesToKopecks` /
  `ratioToPercent`); `/100` и `.toFixed` вне allowlist — lint-ошибка.

## 9. Figma — первоисточник

- Перед реализацией тянуть ноду из Figma («Рентли. Новые экраны сервиса»):
  текст тикета ≠ макет. Размеры и отступы — из инспектора ноды, не с
  глазомера.
- Данные Figma авторитетнее скриншотов-рендеров; при коллизии макета со
  здравым смыслом — вопрос владельцу (консистентность продукта важнее буквы
  макета, но менять без решения нельзя).

## 10. Фиксация решений (живой документ)

- Решение владельца по дизайну → JSDoc компонента (формат «решение владельца
  ДД.ММ») + соответствующий раздел этого файла — **в том же коммите**.
- Новый или изменённый компонент design-слоя → секция на витрине `/ui-kit` —
  в том же коммите.
- Файл поддерживается по принципу «сломал конвенцию — обнови документ»: если
  код и этот файл расходятся, это баг одного из двух, чинятся в одном коммите.
