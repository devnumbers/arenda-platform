# payment-categories

Единый источник правды для дефолтного каталога категорий платежей. Из этого
каталога генерируется код в Go и frontend TS (см. раздел [Генератор](#генератор)
ниже). Канонический источник состава — Figma (см. «Источник каталога»).

## Файлы

- `catalog.json` — сам каталог (40 категорий: слаг, название, иконка, цвет
  подложки) и дефолтный внешний вид пользовательской категории.
- `catalog.schema.json` — JSON Schema (draft 2020-12) для самопроверки каталога.
- `validate-source.mjs` — утилита: валидирует `catalog.json` против схемы через ajv.
- `generate.mjs` — генератор артефактов кода (Go + frontend TS) из каталога.
- `gen/` — исходники генератора: `validate.mjs` (общая ajv-логика + семантические
  проверки), `emit-go.mjs`, `emit-frontend-ts.mjs`, `gofmt.mjs`.
- `package.json` — npm-пакет с devDep `ajv` / `ajv-formats` и скриптами `validate`
  и `generate`.

## Почему это существует

Дефолтный каталог категорий платежей не размножается вручную: БД ссылается на
категорию слагом (каталог живёт в коде — решение карты «Платежи и операции» №5),
а Go (валидация слагов, каталог для API) и frontend (пикеры, иконки, цвета)
получают его из одного нормализованного JSON. Паттерн — `tools/property-attributes`.

## Источник каталога

Канонический состав — Figma-файл «📌​ Рентли. Новые экраны сервиса», фрейм
каталога категорий: `node-id=781-12300`. Название, иконка (компонент Figma
`Icon/Bold/*`) и цвет подложки сняты с этого фрейма; состав подтверждён
пользователем (тикет #447). Категория нейтральна к направлению: доход/расход
выбирает пользователь на платеже, а не в каталоге (ревизия решения #444 от
пользователя, 2026-08-25).

Иконки — имена SVG-ассетов из `apps/frontend/shared/assets/icons/` (серия
`bold-*`, экспорт из Figma-набора `Icon/Bold/*`; выгрузки лежат в
`figma-downloads/`, рабочий файл — `bold-<имя>.svg` с `fill="currentColor"`).
Валидатор проверяет наличие ассета у каждой иконки каталога. Исключение:
`bold-key.svg` существовал до каталога (20×20 экспорт того же Figma-компонента
`Icon/Bold/Key`) и не перезаписывался.

Пользовательские категории каталогом не являются: у них одна дефолтная иконка
на серой подложке (`userCategoryDefault`, решение карты №4).

## Как валидировать

```sh
cd tools/payment-categories
npm install
npm run validate
```

Ожидаемый вывод: `catalog.json: OK (40 категорий)`.

## Генератор

Из каталога генерируются артефакты кода для двух стеков (админка для усилия
«Платежи и операции» вне охвата — решение карты №7). Генератор сначала
валидирует `catalog.json` (схема + уникальность слагов + наличие SVG-ассетов
у всех иконок) и при любой ошибке отказывается что-либо писать.

```sh
cd tools/payment-categories
npm run generate      # или: node generate.mjs
# из корня монорепо:
make categories-gen
```

### Что производит генератор

| Стек | Путь | Назначение |
| --- | --- | --- |
| Go | `apps/backend/internal/payments/domain/zz_categories.gen.go` | Самодостаточный модуль без импортов пакета `domain`: `CategoryCatalogEntry`, `DefaultCategories`, `CategoryBySlug`, `IsValidDefaultCategorySlug`, `UserCategoryStyle`/`UserCategoryDefaultStyle` |
| Frontend TS | `apps/frontend/features/payment-categories/lib/generated/categories.ts` | Типы `PaymentCategorySlug`/`PaymentCategoryEntry`, `paymentCategories`, `userCategoryDefault`, `paymentCategoryBySlug`, `isPaymentCategorySlug` |

Все сгенерированные файлы начинаются со строки
`// Code generated by tools/payment-categories/generate.mjs from catalog.json. DO NOT EDIT.`

### Идемпотентность

Повторный запуск `node generate.mjs` даёт байт-идентичные файлы: каталог —
статические данные, зависящих от времени литералов нет.

### gofmt

Если на машине доступен бинарник `gofmt`, генератор прогоняет Go-артефакт через
него. Если `gofmt` не найден, файл пишется неотформатированным и печатается
предупреждение; CI/Makefile может догнать
`gofmt -w apps/backend/internal/payments/domain/zz_categories.gen.go`.

## Как править

1. Измени `catalog.json`.
2. Запусти `npm run validate` — каталог должен пройти проверку схемы.
3. Запусти `npm run generate` (или `make categories-gen`) и закоммить
   артефакты вместе с каталогом — гейт `make categories-check` падает в CI,
   если артефакты несвежие.

## Структура catalog.json

```jsonc
{
  "version": 1,
  "categories": [
    // порядок массива = канонический порядок UI (порядок Figma)
    { "slug": "rent", "label": "Арендная плата", "icon": "bold-key", "color": "#2B7FFF" }
    // ...ещё 39
  ],
  "userCategoryDefault": { "icon": "bold-other", "color": "#ABAB9C" }
}
```

- `slug` — `[a-z][a-z0-9-]*`, ссылка из БД; уникальность проверяется семантически.
- `icon` — имя SVG-ассета в `apps/frontend/shared/assets/icons/`; валидатор
  проверяет существование файла.
- `color` — HEX (`#[0-9A-F]{6}`), цвет круглой подложки иконки в UI.
- Направление (доход/расход) в каталоге отсутствует: это поле платежа, которое
  выбирает пользователь.
