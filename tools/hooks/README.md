# Harness-хуки

Харнесс-нейтральные скрипты хуков для агентских харнессов (Kimi Code, ZCode):
личный opt-in слой разработчика, не командный гейт. Решение — [#294](https://github.com/devnumbers/arenda-platform/issues/294),
реестр — `docs/agents/tooling.md` (раздел «Harness hooks»), реализация — тикет #301.

## Контракт

JSON события на stdin → exit-код:

- `0` — allow (пропустить);
- `2` — block (stderr уходит в контекст модели как причина блокировки);
- любой другой non-zero и любая внутренняя ошибка скрипта — allow (fail-open,
  как и сам механизм хуков харнесса: это страховка от типовых ошибок агента,
  а не security-барьер).

## Скрипты

### `bash-guard.mjs` — PreToolUse(Bash)

Страж деструктивных shell-команд. Блокирует (exit 2):

- `rm` с рекурсивным флагом (`-r`/`-R`/`--recursive`, включая `-rf`, `-fr`, `sudo rm -rf`, `env`/`xargs`-обёртки, пути вида `/bin/rm`, подстановки `$(rm …)`, `bash -c "rm …"`);
- `git clean` без `-n`/`--dry-run`;
- `git reset --hard`;
- `git push --force` / `-f` (`--force-with-lease` разрешён);
- `docker system prune` / `docker volume prune`;
- `docker compose down` / `docker-compose down` с `-v`/`--volumes` (удаляет
  именованные тома — локальные базы).

Разбор команды best-effort (сегменты `&&`/`||`/`;`/`|`/переводы строк,
подстановки `$(…)`, `bash -c`), не настоящий шелл-парсер: командная строка в
кавычках может дать ложное срабатывание, а экзотические формы — пропуск.
Скрипт машино-уровневый: срабатывает в любом проекте пользователя, поскольку
охраняет компьютер, а не этот репозиторий.

### `stop-gate.mjs` — Stop

Прогоняет гейты пакетов с незакоммиченными правками (staged + unstaged +
untracked) перед завершением хода агента — «заявить о готовности без
проверок» становится механически трудным. Скоуп — только незакоммиченное:
закоммиченное уже гейтится pre-commit-хуком lefthook (`lefthook.yml`), слои
композируются без двойного прогона одного и того же диффа; `git commit
--no-verify` остаётся единственным задокументированным сознательным обходом.

Гейты зеркалят pre-commit (держите списки синхронными):

| Затронутые файлы | Гейт |
| --- | --- |
| `apps/backend/**` | `make backend-lint` |
| `apps/frontend/**` | `npm --prefix apps/frontend run lint` |
| `apps/admin/**` | `make admin-typecheck` и `npm --prefix apps/admin run lint` (параллельно) |
| `apps/backend/db/migrations/**` | `make migrations-lint` (полный прогон; правка миграции задевает и более грубый префикс `apps/backend/` — параллельно стартует backend-lint, это принято) |

Правки вне `apps/**` (docs, tools, корень) гейтов не запускают.
Гейты идут параллельно; вывод упавшего гейта (последние 40 строк) уходит в
stderr вместе с exit 2.

Self-scoping: гейт-команды существуют только в этом репозитории, поэтому
скрипт молча разрешает всё, если репозиторий сессии (поле `cwd` в payload) не
совпадает с чекаутом самого скрипта (сравнение `git-common-dir`, worktrees
включены). Пользовательский конфиг хуков срабатывает во всех сессиях — эта
проверка держит остальные проекты тихими.

## Opt-in подключение (Kimi Code)

Конфиг хуков у Kimi Code только пользовательский: `~/.kimi-code/config.toml`
(подробности — [дока hooks](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html)).
Добавьте два блока, подставив абсолютный путь к своему чекауту репозитория:

```toml
[[hooks]]
event = "Stop"
command = "node /abs/path/to/arenda-planform/tools/hooks/stop-gate.mjs"
# Гейты могут быть небыстрыми на холодном кэше (первый golangci-lint ~40 с);
# 300 с — с запасом.
timeout = 300

[[hooks]]
event = "PreToolUse"
matcher = "Bash"
command = "node /abs/path/to/arenda-planform/tools/hooks/bash-guard.mjs"
timeout = 10
```

Требования: Node ≥ 20.11 (используется `import.meta.dirname`), git и make/npm
для самих гейтов. Ничего устанавливать не нужно — скрипты не имеют
зависимостей.

Kimi Code поддерживает и camelCase-вариант payload (`toolInput.command`) —
оба скрипта читают `tool_input` и `toolInput`, так что контракт совместим и с
ZCode.

### ZCode

Обвязка отложена до зрелости плагинного механизма ZCode: проектные хуки
текущей версией игнорируются by design, командное распространение — только
через плагин (фактура: `docs/research/2026-08-16-quality-gates-hooks.md`).
Скрипты уже харнесс-нейтральны — когда механизм дозреет, подключение
сводится к конфигу.

## Тесты

Контрактные тесты на vitest: скрипты запускаются как подпроцессы ровно так,
как их зовёт харнесс (JSON на stdin → exit-код); внутренности не
импортируются. Тесты Stop-гейта разворачивают одноразовый git-репозиторий с
фейковыми гейтами и вербатим-копией скрипта (чтобы self-scoping указывал на
фикстуру, а не на реальный репозиторий).

```bash
make tools-test        # из корня репозитория (входит в make test и CI)
npm test               # из tools/hooks
```
