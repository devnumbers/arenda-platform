# План 054: календарь-лента по макету Т-Банка — будущее снизу, прошлое сверху, бесконечная в обе стороны (TanStack Virtual `anchorTo: 'end'`)

Карта #1437, решение владельца 18.10 (грилл, подтверждено «да все так»): «Мне не нравится реализация. У тбанка сделано так — снизу будущее, сверху прошлые года. Изучи лучшие практики, лучше — офф доку TanStack Virtual, и сделай без багов; скролл бесконечный; если есть ограничение — там даётся всего +2 месяца». Владелец уточнил: «мы же над бесконечным календарём работаем» — будущее у пикеров без лимита доскролливается бесконечно, всё достижимо и скроллом, и чипом. Колёсники (были 054) съезжают на 055.

## Исследование (официальные источники TanStack Virtual)

- [Chat guide](https://tanstack.com/virtual/latest/docs/chat) и [статья команды](https://tanstack.com/blog/tanstack-virtual-chat): для «чатовых» лент (новое — в конце, история досыпается в начало) у ядра есть **`anchorTo: 'end'`**: «виртуализатор захватывает видимый элемент по ключу, находит его после prepend'а и подправляет offset — элемент остаётся на месте». Прямым текстом: **не нужны ни `column-reverse`, ни инвертированные трансформы, ни ручной `scrollTop += delta`** — компенсация 051/052 переходит в библиотеку как её официальный, обкатанный на чатах контракт.
- Открытие — `scrollToEnd()` (вьюпорт сразу у нижнего края); для SSR/восстановленных экранов — `initialOffset`.
- Требование prepend-стабильности — стабильный `getItemKey` (у нас `monthKey`), index-ключи запрещены. `measureElement` в end-anchored режиме поддержан (паттерн из их примера 1:1 наш).
- Версии: обёртка `@tanstack/react-virtual` 3.14.21 (последняя) расширяет типы ядра, установленное ядро 3.19.6 содержит `anchorTo`/`followOnAppend`/`scrollEndThreshold`/`scrollToEnd()` — **бамп не нужен**, типы прокидываются через `ReactVirtualizerOptions extends VirtualizerOptions`.

## Архитектура

Окно возвращается к восходящему списку: `months = [первый .. последний]`, индекс 0 сверху, последний снизу; вьюпорт якорится к нижнему краю (`anchorTo: 'end'`, `followOnAppend: false` — рост будущего никогда не тянет вьюпорт).

- **Открытие**: `scrollToEnd()` в layout-эффекте до пейнта — «сегодня» + приглушённый контекст у нижней кромки; при правке со значением в прошлом — к месяцу значения (#502, контракт 052). `initialOffset` (ленивый, ≈ maxScroll по точным высотам) страхует первый кадр от гонки «контент на месте, окно рендера от нуля» (репро 16.10, урок 052). bornOffset/clamp/grow-loop открытия умирают.
- **Рост прошлого** (сторона сверху): prepend — `setFirstMonth(раньше)` + счётчик; библиотека держит позицию по ключу. Триггер — приближение к верхнему краю (порог 3000px). Бесконечно, если пол прошлого не задан (#1393); при заданном поле (#498 «сегодня», #805 minDate) — жёсткий край: месяц пола **минус 2 приглушённых месяца контекста**.
- **Рост будущего** (сторона снизу): append — счётчик; новые месяцы за пределами вьюпорта, позиция не сдвигается по определению. Бесконечно у пикеров без maxDate (начало аренды, плановые платежи — дни выбираются по обычным правилам); при maxDate — жёсткий край: месяц maxDate **плюс 2 приглушённых** (как было).
- **Симметрия краёв** (слова владельца «если есть ограничение — даётся всего +2 месяца»): каждый жёсткий край получает ровно 2 приглушённых месяца контекста (сверху и снизу); открытые стороны бесконечны с порциями 6 месяцев.
- **Чип «Месяц Год ⌄»**: прыжок в любой месяц в любую сторону — в окне `scrollToIndex`, за краем — доращивание соответствующей стороны и скролл после рендера (тап-тишина); watchdog 052 (setTimeout-гвард с measure-сбросом) остаётся.
- **Мьют контекста**: приглушённые месяцы за жёстким краем — с обеих сторон (`beyondMaxDate` есть, добавляется `beyondFloor`).

**Снимается как superseded**: desc-модель 053 (`topIdx`, `listCalendarMonthsDescending`, «верх фиксирован», бесконечное-будущее-через-прыжок), `bornOffset`, «ноль программных записей scrollTop» как e2e-инвариант (библиотека пишет по дизайну — теперь она отвечает за компенсацию).

## Репро и уроки проводки (18.10)

- **«Лента уезжает в 2324 год»**: `anchorTo: 'end'` — стриминговый контракт («конец списка — сохраняемая кромка»): при измерении новых строк у края ядро прикладывает вьюпорт к растущему концу (`wasAtEnd → applyScrollAdjustment(totalDelta)`), каждый append тянул вьюпорт вниз, новый scroll-ивент рождал новый append — каскад ~300 лет при открытии. Лечение: `scrollEndThreshold: -1` (пин мёртв; prepend-восстановление идёт по отдельному якорному пути без порога) + `followOnAppend: false`.
- **Гистерезис «одна порция на приближение» и рост только в направлении жеста** (append при движении вниз, prepend при движении вверх, первый кадр — без решений): страховка от любых петель подстроек у края.
- **Открытие** — не `scrollToEnd`, а `scrollToIndex(anchor)` (контракт бага-2: месяц якоря у верхней кромки; scrollToEnd прятал «сегодня» за фолд на телефонном вьюпорте). `initialOffset` — ленивый по точным высотам до якоря.
- **Инвариант e2e**: компенсированный prepend — `topΔ + stΔ ≈ shΔ` (подстройка вернула вставку), append — `topΔ + stΔ ≈ 0`; подстройка библиотеки может доезжать 1-2 кадра — окно сходимости 3 кадра. Прыжок некомпенсированной вставки в кадре скролла чёрным ящиком rAF-пробы неотличим — его держит фел-чек владельца.
- **Флейк «страница под пикером»**: свап RSC-дерева холодного старта роняет scrollY в ноль после stickyScroll — хелпер `ensurePageScrolled` докручивает фон под накрытой страницей (hidden-бокс остаётся скролл-контейнером, канон лока).
