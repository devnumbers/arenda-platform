# 041 — Лок фона без прыжка позиции

- **Status**: TODO
- **Baseline**: bfd817d54; развивает план 005 (канон `useBodyScrollLock`)
- **Severity**: HIGH (баг, feel-check владельца 16.10)
- **Origin**: карта #1437, догонка feel-check владельца
- **Estimated scope**: useBodyScrollLock.ts, e2e scroll-isolation (+1 тест), ~40 строк

## Problem

Feel-check владельца 16.10: «при открытии модалок страница назад
отходит». Воспроизведено на стенде bfd817d54 (замер 16.10): фон
прокручен на 800, открытие календарного пикера (фуллскрин-поверхность)
сбрасывает `scrollY` в **0**, и после закрытия позиция не возвращается.

Механизм: `useBodyScrollLock` ставит на `html` инлайн
`overflow: clip` — `html` перестаёт быть скролл-контейнером, и браузер
сбрасывает viewport-скролл. Потребители хука — календарный пикер,
шит фильтров истории, пикеры визардов (`wizard-chrome`), приглашение
участников, поиск адреса. Radix-модалки (react-remove-scroll) позицию
хранят — проверено на стенде («Поддержка»: 800 сохранён) — их не трогаем.

Требование владельца: страница не сдвигается и не прыгает при открытии и
закрытии поверхностей. Лок фона при этом остаётся (жест у края
поверхности не скроллит страницу — конвенция тикета #1417); убирается
только прыжок.

## Target

`shared/lib/hooks/useBodyScrollLock.ts` — сохранить позицию скролла на
время лока. Итоговая механика (каждый слой подтверждён замерами на
стенде 16.10; путь к ней прошёл через пять опровергнутых гипотез —
focus, scrollIntoView, anchoring, snap, rAF-тайминг):

1. **hidden вместо clip по оси Y**: html инлайн `overflow: clip hidden`
   (x — clip: скролл-контейнер по X не создаётся, sticky жив, канон
   #709; y — hidden: hidden-бокс остаётся скролл-контейнером и хранит
   оффсет, программная запись в него работает — clip сбрасывал
   viewport-скролл с потерей позиции).
2. **Модульный страж позиции, вооружённый до любого монтирования.**
   Прыжок движка при вставке оверлея случается синхронно с мутацией DOM,
   раньше всех эффектов React (протокол 16.10: MutationObserver видит
   документ уже сдвинутым; доверенный мгновенный скролл без единого
   вызова scroll-API). Страж — пара слушателей scroll документа уровня
   модуля: трекер последней стабильной позиции и клампер. Эффект хука
   (layout-фаза, изоморфный useLayoutEffect) применяет стили и
   инкрементирует счётчик активных локов.
3. **Трекер заморожен на время лока** (`lockCount === 0`): прыжок
   приходит тем же scroll-событием, на котором клампится, и слушатели
   диспатчат по порядку регистрации — незамороженный трекер успевал
   запомнить прыгнутое значение раньше клампа, и кламп видел
   «смещение равно трекеру» (протокол: в журнале одно событие, страж
   молчал).
4. **Коррекция — макротаска (setTimeout 0)**: присвоение scrollTop тому
   же скроллеру внутри его же scroll-события Chromium молча отбрасывает
   (~110 срабатываний стража в диспетчере без эффекта). setTimeout, не
   rAF — headless e2e не обязан тикать кадры.

Смежная гигиена того же замера — `calendar-date-picker.tsx`: все шесть
`scrollIntoView` заменены на `scrollListToMonth` (прокрутка только
внутренней ленты геометрией; scrollIntoView реквизирует всех скролл-
предков и под фиксированным оверлеем двигает и документ).

Поверено: позиция фона сохраняется при открытии и закрытии (e2e, 390×844),
жест/колесо у края ленты не уезжают в фон (6 существующих тестов
конвенции зелёные), вложенный лок LIFO (шит фильтров → пикер периода),
Radix-модалки не тронуты.

JSDoc хука переписан под фактическую механику (см. файл).
