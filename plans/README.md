# Мульти-скролл: изоляция скроллеров (карта #1416, тикет #1417, 2026-10-14)

Симптом «на странице несколько скроллов» (страница истории + бесконечный
календарь): одно правило на слой, планы согласованы как одна конвенция.
Рекогносцировка тикета проверена по месту на 7a963de1a — уточнения встроены
в планы (у календарных лент contain уже есть; модалки уже канон; реальный
список больных поверхностей — четыре, внутренних лент — семь).

## Конвенция — одно правило на слой

| Слой | Правило | Реализация / эталон |
| --- | --- | --- |
| Документ | Единственный видимый скроллбар продукта; никаких overscroll-запретов на html/body (системный pull-to-refresh жив, ADR 0031); `overflow-x: clip`, не hidden (sticky жив, #709); фон замораживается на время модальных поверхностей | globals.css:954-1006 (#865/#925/#709, решение 01.10), e2e `scroll-shift.spec.ts` |
| Фуллскрин-поверхность | `useBodyScrollLock()` в корневом компоненте — фон заморожен на всё открытие | `calendar-date-picker.tsx:185,601` (канон 13.10); план 005 раскатывает на остальные четыре |
| Шит (Modal/vaul) | Лок — Radix Dialog из коробки; тело — `overflow-y-auto overscroll-contain` | `modal.tsx:136` (канон) |
| Внутренняя лента | `overscroll-y-contain` (жест у края гаснет в ленте) + `[scrollbar-width:none]` (индикатор один — корневой) | `wheel-picker.tsx` (эталон); план 006 раскатывает на семь мест |

Вне правила: textarea-редакторы (`text-field.tsx` autogrow — не лента) и
витрина `/ui-kit` (демо, не продукт).

## Решения

- **Корневой скроллбар остаётся видимым** (решение владельца 01.10, DESIGN.md
  §14, не пересматривается): «второй скролл» под поверхностями лечится
  скрытием внутренних скроллбаров, не корневого. Видимый трек под фиксированной
  поверхностью — норма: гюттер стабилен, колонка не прыгает.
- **Глобальный `overscroll-behavior` на html/body запрещён**: запрет убил бы
  нативный pull-to-refresh (Android браузер/WebAPK — ADR 0031, ротация
  12.10) и iOS-standalone кастомный PTR (`PullToRefresh.tsx:96`, гейт
  `isIosDevice()`). Запреты — точечно на внутренних лентах; точечный гард
  на время жеста уже существует (`ptr-suppress-overscroll`,
  `PullToRefresh.tsx:79`).
- **Вложенность поверхностей** (шит фильтров → пикер периода поверх — первая
  в продукте): лок вкладывается LIFO — React очищает эффекты детей раньше
  родительских, restore хука корректен; JSDoc хука правится планом 005.
  С Radix-локом конфликтов нет — стек «календарный пикер → шит месяца» уже
  живёт.
- Решения опираются на слова владельца (01.10 скроллбар, 12.10 PTR/ADR 0031,
  13.10 лок) — новых слов не требуют; утверждение планов — при ревью тикета
  #1417 (карта ждёт «утверждённый владельцем дизайн фикса»).

# Переходы страниц: отказ (карта #1416, тикет #1419, 2026-10-14)

Вопрос тикета: играть ли анимированный переход между маршрутами и какой.
Прототип собран и проверен вживую на seeded-стенде (пилюля-переключатель
на cookie, три варианта на живых маршрутах демо-вертикали «Объекты» →
деталь): **0 · Статус-кво** (базовая линия), **1 · Появление + слайд**
(View Transitions: кросс-диссольв на разделы/табы, push/pop на погружение,
слайд-зеркало на «Назад» детали через тип детерминированного push #1374;
планшет/ПК — деградация в появление), **2 · Общий элемент** (морф круга
карточки объекта в hero детали; пара по имени играет и на браузерный
«Назад»). Проверено кадрами: слайд/поп зеркальны, хром (TabBar/сайдбар/
пилюли) неподвижен, reduced-motion, якорный /history, статус-кво честен
(нуль вызовов startViewTransition), консоль чистая.

**Решение владельца (14.10.2026, по живому прототипу): переходы не нужны —
отказ полностью.** Тема закрыта второй раз (первый — #867, 25.09.2026);
возврат — только явным словом владельца с чистого листа. Код прототипа
в dev не вливался — дерево возвращено к fbffac261. Аддитивные швы из
аудита #1418, отложенные «в часть переходов» (своп шагов визарда, вход
экрана успеха, свап шапки в поиск), умирают вместе с темой — не
открываются. Фиксы 005–017 не затронуты: это движение внутри
поверхностей, не смена маршрутов.

Актив — если тема когда-нибудь вернётся (первоисточники: #867 — ветка
prototype/page-transitions-867; #1419 — стенда не осталось, кадры и
выводы в тикете):

- Технология рабочая: React `<ViewTransition>` (импорт из `'react'`) в
  App Router Next 16.4 без конфигурации — компонент экспортирует
  вендоренная копия react внутри next; в npm-типах react 19.2 его нет —
  нужна ссылка `/// <reference types="react/canary" />`.
  `transitionTypes` на `<Link>`/`router.push` типизированы и доставляются.
- Канон reveal без провалов (#867) подтвержден: старый кадр — неподвижная
  непрозрачная подложка, новый проявляется поверх. Хром выживает переход
  через сырой `view-transition-name` на персистентном fixed-узле
  (TabBar/сайдбар/пилюли) — пары без анимаций слоем над страничными
  снимками.
- Грабли, оплаченные временем: пара по имени образуется только в том же
  коммите, что и навигация — Suspense-фолбэк обязан нести имя, иначе морф
  молчит вовсе; псевдоэлементы `::view-transition-*` вешаются на html —
  селектор `html[x] ::view-transition-*` с пробелом не матчится (верен
  только `html[x]::view-transition-*`); `suppressHydrationWarning` не
  исправляет текст (серверный текст пилюли залипает в DOM — лечится
  дефолтом на первом кадре + синком из cookie после гидратации);
  браузерный «Назад» (popstate) типов не несёт — зеркало слайда играется
  только детерминированным push (#1374).
