# CHANGELOG

Журнал изменений продукта. Каждая запись привязана к дате и описана понятным для менеджера и продакта языком — без лишних технических подробностей.

Формат одной записи:

- **Добавлено** — новые фичи, интеграции, возможности.
- **Исправлено** — баги, дефекты, регрессии.
- **Изменено** — доработки поведения, улучшения, рефакторинг.

## 2026-06-26

### Добавлено
- В операции аренды добавлено поле «название платежа»: теперь при создании и редактировании операции можно указать короткое название до 50 символов, которое возвращается в ответе API.
- В регулярные операции добавлено поле «название платежа» и поддержка ежегодной периодичности: при создании и редактировании регулярной операции можно задать название до 50 символов и выбрать периодичность «раз в месяц» или «раз в год», которая учитывается при генерации запланированных платежей.
- Добавлены шаги формы создания операции: основная информация о платеже, дата и периодичность, SMS-напоминание за 1, 3 или 7 дней, а также экран успеха с переходом к финансам и объекту.
- Добавлена страница редактирования объекта недвижимости: владелец может изменить тип, адрес, название и описание, а также добавить или удалить фотографии.
- Добавлен бэкенд endpoint для удаления фотографий объекта: файл удаляется из хранилища, а запись — из базы, с проверкой прав собственника и принадлежности фото к объекту.
- Добавлен административный endpoint для возврата платежей по подписке: доступен только пользователям с ролью admin, поддерживает полный и частичный возврат, после успешного возврата подписка переводится на базовый тариф.
- Добавлен административный endpoint для просмотра списка платежей по подписке: доступен только пользователям с ролью admin, поддерживает фильтрацию по статусу и пагинацию, в ответе отображается телефон владельца платежа.
- Добавлен компонент выбора типа объекта для формы редактирования: read-only поле с выпадающим списком вариантов недвижимости.

### Исправлено
- Исправлена ошибка 409 при возврате зависших платежей в статусе «ожидание»: администратор теперь может отменить такие платежи, и они будут переведены в статус возврата с даунгрейдом подписки на базовый тариф.
- Исправлено сохранение периодичности при редактировании регулярной операции: выбранное значение «раз в месяц» или «раз в год» теперь корректно записывается в базу данных.
- Исправлена обработка тела запроса при административном возврате платежа: частичный возврат теперь корректно распознаётся независимо от способа передачи тела запроса, а некорректный JSON возвращает ошибку 400.
- Уточнена модель статуса платежа подписки: теперь в API отражены состояния полного и частичного возврата.
- Улучшена надёжность административного возврата платежа: внешний вызов провайдера выполняется без удержания блокировки строки в базе, а ошибки из-за неподходящего статуса платежа возвращают 409 Conflict.
- Исправлен ввод адреса в форме редактирования: ручной набор текста больше не сбрасывается после выбора подсказки.
- Исправлена форма редактирования объекта: введённые данные не сбрасываются при фоновом обновлении информации об объекте.
- Исправлен компонент выбора типа объекта в форме редактирования: улучшена доступность и корректность разметки выпадающего списка.
- Улучшена валидация формы редактирования объекта: ошибки по обязательным полям теперь показываются под каждым полем.
- Усилена безопасность удаления фотографий объекта: теперь фото удаляется только в том случае, если оно действительно принадлежит указанному объекту и собственнику.
- Улучшена надёжность удаления фотографий объекта: запись в базе удаляется внутри транзакции, а очистка файла в хранилище выполняется после фиксации транзакции.
- В сервисе удаления фотографий убрана прямая работа с ошибками базы данных — все Not Found‑случаи обрабатываются через единый прикладной механизм.

- Подготовлен дизайн страницы создания арендатора: форма с именем, фамилией, отчеством, телефоном и комментарием, черновик в sessionStorage и экран успеха с переходом к списку арендаторов или к финансам.

- Реализован первый шаг создания объекта: выбор типа недвижимости через чипы и кнопку «Продолжить».
- Добавлен сервис подсказок адресов DaData: по запросу возвращаются варианты с адресной строкой и городом, чтобы ускорить заполнение адреса объекта.
- Добавлен второй шаг создания объекта: ввод адреса с подсказками DaData и выбором адреса из выпадающего списка.
- Добавлена шапка и индикатор прогресса по шагам на странице создания объекта.
- Добавлен второй шаг создания аренды: выбор дня оплаты, даты начала и окончания аренды.
- Добавлен экран успеха создания аренды с переходом к списку объектов или добавлению арендатора.
- Реализован пошаговый wizard создания аренды: цена и залог, даты аренды, экран успеха; черновик шага сохраняется в sessionStorage.
- Добавлены автоматические скриншоты сценария создания аренды для мобильной и десктопной версий.
- Фоновый процесс биллинга теперь дополнительно проверяет у провайдера статус «зависших» платежей за апгрейд тарифа, созданных более 5 минут назад, и автоматически завершает успешные или отмечает неудачные платежи.
- Бэкенд научился обрабатывать возвраты платежей из личного кабинета Т-Банка: при получении уведомления о полном или частичном возврате подписка немедленно переводится на базовый тариф, а лишние объекты архивируются.

- Устранены замечания финального код-ревью страницы объекта: устранены пробелы в инвалидации кеша при завершении аренды и возврате залога, убрано дублирующее меню «Действия», скрыта неактивная кнопка «Завершить» для завершённых договоров, улучшены ARIA-атрибуты меню, добавлена обработка ошибок запросов аренды и операций, а галерея переведена на `next/image` с приоритетной загрузкой первого фото.
- Устранены замечания по качеству кода на странице объекта: у модальных окон появились доступные имена (`aria-label`), стили суммы залога вынесены из inline-атрибутов в CSS-модуль, маршрут редактирования объекта взят из конфигурации маршрутов, а кнопка «Завершить аренду» скрыта, если обработчик не передан.
- Исправлена страница создания арендатора: убран дублирующий заголовок в шапке, кнопки на экране успеха вынесены за пределы карточки по макету Figma, добавлена маска ввода телефона в формате `+7 (XXX) XXX-XX-XX`, а обновление страницы на экране успеха теперь сохраняет состояние благодаря черновику в sessionStorage.
- Исправлен возврат залога по аренде: операция защищена от повторного создания по выделенной категории, доступна для завершённых, требующих действия или архивных договоров, а ошибки при чтении договора обрабатываются единообразно.
- Исправлена локальная передача тела запроса через прокси: запросы к бэкенду (например, проверка кода авторизации) теперь обрабатываются корректно, без ошибки `fetch failed`.
- Обработка webhook‑уведомлений Т‑Кассы стала асинхронной: бэкенд теперь сразу возвращает провайдеру ответ `200 OK` с телом `OK`, а активацию подписки и привязку карты выполняет в фоне. Это исключает 10‑секундный таймаут Т‑Кассы при медленной сети или долгой транзакции.
- Исправлена локальная конфигурация подключения к Т‑Кассе: пароль терминала теперь корректно обрабатывается при запуске бэкенда, что позволяет подключить sandbox‑режим оплаты подписок без ошибок.
- Исправлена обработка ошибок и уведомлений адаптера Т‑Кассы: убран некорректный игнор дублей клиента, скорректированы коды ошибок при удалении карты, обновлён тип уведомления о привязке карты и сохраняются тела HTTP‑ошибок для диагностики.
- Устранена race condition при удалении способа оплаты: проверка активности карты теперь выполняется внутри транзакции.
- При автопродлении подписки запрос на инициацию платежа теперь передаётся как рекуррентный, чтобы провайдер корректно связал его с сохранённой картой и разрешил безакцептное списание.
- Коды ошибок провайдера сохраняются в неудачных платежах при автопродлении для упрощения диагностики.
- Обработка webhook‑уведомлений о привязке карты Т‑Кассы теперь поддерживает как актуальный тип `NotificationAddCard`, так и устаревший `AddCard`.

## 2026-06-24

### Добавлено
- Операции аренды получили статус жизненного цикла: запланирована, просрочена, оплачена или получена. Новые операции создаются со статусом «запланирована» и переводятся в завершённый статус только по действию собственника; доходные операции отмечаются как «получено», расходные — как «оплачено».
- Запланированные операции с прошедшей датой автоматически помечаются как просроченные, при этом создаётся напоминание «Операция просрочена», которое отправляется через единую подсистему уведомлений один раз при переходе статуса.
- В личном кабинете появилась возможность завершить все активные сессии пользователя одной кнопкой.
- Исправлены адаптивы страницы логина. На десктопе (≥1200px) снова используется двухпанельный layout: слева — фон с 3D-логотипом, справа — белая панель с узкой карточкой формы по центру. На планшетах и мобильных фон покрывает весь экран, белая карточка формы лежит поверх него, а 3D-логотип показывается только на планшетах (768–1199px). Breakpoints переписаны с использованием max-width.
- На экране ввода SMS-кода номер телефона в подзаголовке теперь остаётся на одной строке и не переносится по цифрам на узких экранах.
- На странице логина добавлена верхняя панель: на экране ввода номера — кнопка закрытия, возвращающая на главную, на экране ввода кода — кнопка назад к номеру и кнопка поддержки. Панель адаптирована под все breakpoint'ы.
- На странице логина обновлён правовой блок под кнопкой входа: теперь текст соответствует макету Figma и содержит ссылки на политику конфиденциальности и обработку персональных данных.
- На странице логина теперь показывается таймер повторной отправки SMS и на экране ввода номера телефона. Таймер сохраняется в localStorage, не сбрасывается при перезагрузке и синхронизируется между вкладками. Расположение текста и таймера в кнопке приведено к макету Figma.
- Реализована страница «Мои объекты»: список объектов с карточками, статусами, фильтрами по типу и статусу, сортировкой по названию, пустым состоянием, загрузкой и обработкой ошибок; фильтры и сортировка синхронизируются с адресной строкой.
- Добавлены страницы архивных объектов и создания нового объекта.

### Изменено
- Финансовый блок дашборда теперь разделяет фактические и запланированные/просроченные операции: основные цифры дохода, расхода и прибыли считаются только по оплаченным и полученным операциям, а суммы в статусах «ожидает оплаты» и «просрочена» показаны отдельной строкой.
- Страница дашборда приведена к макетам Figma на всех breakpoint'ах: обновлены шапка, карточка ближайшей аренды, списки объектов и арендаторов, финансовый блок и ближайшие платежи. Добавлены пустые состояния для каждой секции.
- Боковое меню личного кабинета обновлено по Figma: убрана правая граница, закреплено сверху, обновлены размер логотипа, иконки пунктов и цвета активного/неактивного состояния.
- Мобильное нижнее меню обновлено по Figma: теперь используются отдельные bold-иконки, пункты распределяются равномерно, активный пункт подсвечивается синим цветом.
- Сессия входа в личный кабинет теперь имеет скользящий срок жизни: базовый срок 7 дней, при активности продлевается ещё на 7 дней, но не дольше 30 дней с момента входа. Это снижает риск угона аккаунта при компрометации cookie.
- Страница «Мои объекты» доведена до макетов Figma: обновлены карточки объектов, статусы «Арендован», «Аренда завершена», «Не арендован» и «На ремонте», фильтры и сортировка, пустое состояние, скелетон загрузки, а также страница создания объекта.

### Добавлено
- Интеграция с платёжным провайдером T‑Касса: оплата подписки, автопродление, привязка и отвязка карты, обработка уведомлений провайдера.

### Исправлено
- Повторная попытка апгрейда тарифа через T‑Касса теперь возвращает ту же ссылку на оплату, что была получена при первой инициализации.
- Webhook привязки карты от T‑Касса обрабатывается только при успешном статусе привязки; неуспешные уведомления игнорируются.
- Корректные адреса и формат запросов к API T‑Кассы: базовый URL по умолчанию теперь `/v2/`, идентификатор платежа передаётся строкой, а автопродление не отправляет флаг `Recurrent`.
- Первый платёж через T‑Кассу использует корректный тип инициатора операции (`1`), автопродление — тип `R` без сохранения карты.
- Настройка `APP_BASE_URL` теперь обязательна для T‑Кассы и проверяется на корректную схему; в staging и production принимается только `https://`.
- Идентификатор карты и срок действия в способах оплаты шифруются в базе данных наравне с токеном провайдера.
- Отвязка карты в T‑Кассе не блокирует локальное удаление, если карта уже отсутствует у провайдера.
- Проверка подписи webhook T‑Кассы выполняется constant-time, а также сверяется `TerminalKey` и исключается поле `Data` из подписи.
- Терминальные неуспешные статусы T‑Кассы (`CANCELED`, `DEADLINE_EXPIRED`, `REVERSED`, `REFUNDED` и др.) корректно мапятся в failed вместо pending.
- Повторный webhook об успешном автопродлении больше не продлевает подписку дважды: продление привязано к моменту успешной оплаты.
- Webhook о неуспешном автопродлении переводит активную подписку в grace-период.
- Удаление активного способа оплаты запрещено, пока он используется для автопродления.
- Сохранение provider reference после инициализации платежа выполняется под строковой блокировкой и только для платежа в статусе pending, чтобы исключить параллельные обновления.

## 2026-06-21

### Добавлено
- Добавлена полная автоматическая E2E-проверка через Bruno: последовательные пользовательские сценарии, SQL-контроль состояния базы, граничные случаи, параллельные нагрузочные проверки на одном объекте недвижимости, а также прогоны для нескольких случайных пользователей с дополнительными race-сценариями (архивация/разархивация, обновление операции, даунгрейд тарифа при создании объектов).

### Изменено
- Устранены остатки технического долга по итогам повторного код-ревью: защитные ветки `WithTx` заменены на прямое приведение типа, SQLC-генерация переехала в `internal/platform/generated/postgres` и включила prepared-запросы.
- Список договоров аренды теперь подгружает контакты арендаторов одним пакетным запросом вместо отдельного запроса на каждую аренду.
- Ручной SQL в обновлении статуса периодических операций по объекту заменён на сгенерированный SQLC-запрос.
- Кэш тарифов теперь автоматически инвалидируется по TTL; время жизни кэша настраивается через `TARIFF_CACHE_TTL`.
- Доменные пакеты больше не зависят от shared-утилит: телефон и дата продублированы локально в соответствующих доменах.

### Исправлено
- В production-логи больше не попадают сырые ошибки внешних платёжного и SMS-провайдеров: номера телефонов, данные карт и токены очищаются перед записью в лог.
- Устранена утечка соединения PostgreSQL при вызове `QueryRow` без последующего `Scan`: добавлен явный метод закрытия строки и fallback-очистка через финализатор.
- Исправлено перестроение графика арендных платежей при изменении даты начала договора: исторические операции и ручные исключения больше не удаляются безвозвратно, а расписание пересчитывается только начиная с ранней из двух дат начала.
- Устранены состояния гонки при одновременном изменении объекта недвижимости и периодической операции: сущность теперь читается и изменяется внутри одной транзакции под строковой блокировкой.
- Архивация и разархивация объекта недвижимости теперь выполняются под строковой блокировкой: параллельные попытки не приводят к двойной архивации и не нарушают лимит активных объектов.
- Убран межконтекстный импорт property-домена в leases-адаптере; проверка активного объекта использует локальное строковое сравнение.
- Операции с напоминаниями и возобновление периодической операции теперь открывают транзакцию до чтения сущности и используют `FOR UPDATE`, чтобы исключить потерю изменений при параллельных запросах.
- В платёжном потоке billing устранены состояния гонки между провайдером и базой данных: восстановление после ошибки списания теперь уточняет статус платежа у провайдера, прежде чем переводить подписку в grace-период.
- Успешное списание при автопродлении и подтверждение платежа больше не откатываются из-за ошибок обновления подписки или архивации объектов: эти шаги выполняются отдельно после фиксации платежа, а сбой фиксируется в логах для ручной проверки и восстанавливается при следующем проходе.
- При апгрейде тарифа provider reference и сохранённый способ оплаты фиксируются в одной транзакции сразу после инициализации платежа; повторный запрос восстанавливает пропавшую ссылку у провайдера.
- Усилена надёжность освобождения PostgreSQL advisory lock в billing worker: cleanup выполняется в отдельном коротком контексте и фиксируется в логах, чтобы lock не зависал при отмене родительского контекста.
