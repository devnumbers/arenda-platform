# CHANGELOG

Журнал изменений продукта. Каждая запись привязана к дате и описана понятным для менеджера и продакта языком — без лишних технических подробностей.

Формат одной записи:

- **Добавлено** — новые фичи, интеграции, возможности.
- **Исправлено** — баги, дефекты, регрессии.
- **Изменено** — доработки поведения, улучшения, рефакторинг.

## 2026-06-20

### Добавлено
- Добавлена документация по запуску локального нагрузочного тестирования read endpoint'ов через `vegeta`.
- Добавлен двухтерминальный запуск perf-стенда: отдельно backend с живыми логами, отдельно нагрузочный тест.
- Добавлены режимы автоматического подбора RPS: `sustainable` (max RPS при p95 < 500 мс и 100 % success) и `breakdown` (max RPS до достижения 10 % ошибок).
- Добавлены `make perf-sustainable` и `make perf-breakdown`.
- Добавлена диагностика узкого места после нагрузочных запусков: backend, PostgreSQL, генератор или неизвестная причина.
- Добавлена локальная диагностика пула соединений backend для нагрузочных прогонов.
- Добавлены предупреждения о конкуренции за backend pool и признак нестабильной границы в отчётах нагрузочного тестирования.
- Добавлена локальная диагностика медленных обращений к базе данных во время нагрузочных прогонов.

### Исправлено
- Диагностические логи базы данных теперь показывают понятные названия операций вместо служебного placeholder.
- В billing убраны внешние вызовы платёжного провайдера изнутри транзакций базы данных: автопродление фиксирует pending-платёж в отдельной транзакции, а уже потом обращается к провайдеру. При сбое подписка корректно переходит в grace-период.
- Исправлена утечка транзакции в `changeTariffUpgrade` при ошибке инициализации платежа у провайдера.
- Просмотр договоров аренды больше не изменяет их статус в базе данных; статус рассчитывается при отображении.
- Просмотр списка периодических операций и карточки операции больше не создаёт записи в базе; горизонт операций обновляется только при создании, изменении и возобновлении.

### Изменено
- Код нагрузочного стенда приведён в соответствие с линтером.
- Для perf-режима настроен более устойчивый пул соединений к PostgreSQL с запасом для диагностики и служебных подключений.
- `perfvegeta` сохраняет все промежуточные прогоны в отчётах и явно помечает результат, если раньше backend'а упёрся генератор нагрузки.
- `perfvegeta` отдельно показывает лучшую успешную точку, первый отказ по SLO и первый отказ генератора нагрузки.
- `perfvegeta` делает паузу между пробами и подтверждает найденную sustainable-точку повторными прогонами.
- Базовая точка локального sustainable-прогона теперь сразу проверяет нагрузку 5000 RPS для `/me`.
- Локальный perf-профиль подключений к базе данных приведён к единому значению с запасом для диагностики.
- Локальные настройки пула базы данных и быстрых успешных access logs больше не задаются через env.
- Make-команды perf-стенда теперь запускаются из корня репозитория и по умолчанию проверяют `/me`.
- Seed для perf-стенда стал объёмнее: list endpoint'ы теперь читают реалистично заполненные списки.
- `GET /me` стал выполнять меньше повторных чтений при уже загруженной сессии.

### Удалено
- Убран k6-оркестратор и k6-скрипты нагрузочного тестирования: генератор в Docker на локальной машине упирался в собственный потолок раньше бэкенда. Write endpoint'ы временно выведены из локального perf-покрытия.
- Убрана генерация фикстур для write endpoint'ов из perfseed: сейчас harness тестирует только read endpoint'ы.
- Убраны лишние perf-команды, которые дублировали запуск или относились к старому harness.

## 2026-06-19
