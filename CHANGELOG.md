# CHANGELOG

Журнал изменений продукта. Каждая запись привязана к дате и описана понятным для менеджера и продакта языком — без лишних технических подробностей.

Формат одной записи:

- **Добавлено** — новые фичи, интеграции, возможности.
- **Исправлено** — баги, дефекты, регрессии.
- **Изменено** — доработки поведения, улучшения, рефакторинг.

## 2026-06-22

### Добавлено
- Добавлен coverage gate для ручной Bruno-коллекции и системных E2E-сценариев: теперь прогон E2E не стартует, если публичные endpoint'ы backend не покрыты запросами в коллекциях.
- Ручная Bruno-коллекция и системные E2E-тесты дополнены недостающими GET-запросами: список договоров аренды, карточка договора, карточка операции, карточка периодической операции и карточка контакта арендатора.
- В системные E2E-сценарии добавлена проверка обработки платёжного webhook'а: входящий webhook об успешной оплате существующего платежа, проверка активной подписки и SQL-контроль записи об оплате.

### Изменено
- Приведён в порядок инструментарий тестирования: системные E2E-тесты, SQL-проверки и оркестратор вынесены в `tools/e2e/`, а в `tools/bruno/arenda-api/` оставлены только ручные API-запросы. Ранее разрозненные коллекции напоминаний и подписок влиты в основной сценарий, дублирующие тесты удалены.
- Улучшена стабильность локальных E2E-прогонов: тестовые пользователи создаются с уникальными номерами телефонов для каждого запуска, чтобы повторные прогоны не конфликтовали с данными предыдущих запусков в локальной базе.

## 2026-06-21

### Добавлено
- Добавлена полная автоматическая E2E-проверка через Bruno: последовательные пользовательские сценарии, SQL-контроль состояния базы, граничные случаи, параллельные нагрузочные проверки на одном объекте недвижимости, а также прогоны для нескольких случайных пользователей с дополнительными race-сценариями (архивация/разархивация, обновление операции, даунгрейд тарифа при создании объектов).

### Изменено
- Устранены остатки технического долга по итогам повторного код-ревью: защитные ветки `WithTx` заменены на прямое приведение типа, SQLC-генерация переехала в `internal/platform/generated/postgres` и включила prepared-запросы.
- Список договоров аренды теперь подгружает контакты арендаторов одним пакетным запросом вместо отдельного запроса на каждую аренду.
- Ручной SQL в обновлении статуса периодических операций по объекту заменён на сгенерированный SQLC-запрос.
- Кэш тарифов теперь автоматически инвалидируется по TTL; время жизни кэша настраивается через `TARIFF_CACHE_TTL`.
- Доменные пакеты больше не зависят от shared-утилит: телефон и дата продублированы локально в соответствующих доменах.

### Исправлено
- В production-логи больше не попадают сырые ошибки внешних платёжного и SMS-провайдеров: номера телефонов, данные карт и токены очищаются перед записью в лог.
- Устранена утечка соединения PostgreSQL при вызове `QueryRow` без последующего `Scan`: добавлен явный метод закрытия строки и fallback-очистка через финализатор.
- Исправлено перестроение графика арендных платежей при изменении даты начала договора: исторические операции и ручные исключения больше не удаляются безвозвратно, а расписание пересчитывается только начиная с ранней из двух дат начала.
- Устранены состояния гонки при одновременном изменении объекта недвижимости и периодической операции: сущность теперь читается и изменяется внутри одной транзакции под строковой блокировкой.
- Архивация и разархивация объекта недвижимости теперь выполняются под строковой блокировкой: параллельные попытки не приводят к двойной архивации и не нарушают лимит активных объектов.
- Убран межконтекстный импорт property-домена в leases-адаптере; проверка активного объекта использует локальное строковое сравнение.
- Операции с напоминаниями и возобновление периодической операции теперь открывают транзакцию до чтения сущности и используют `FOR UPDATE`, чтобы исключить потерю изменений при параллельных запросах.
- В платёжном потоке billing устранены состояния гонки между провайдером и базой данных: восстановление после ошибки списания теперь уточняет статус платежа у провайдера, прежде чем переводить подписку в grace-период.
- Успешное списание при автопродлении и подтверждение платежа больше не откатываются из-за ошибок обновления подписки или архивации объектов: эти шаги выполняются отдельно после фиксации платежа, а сбой фиксируется в логах для ручной проверки и восстанавливается при следующем проходе.
- При апгрейде тарифа provider reference и сохранённый способ оплаты фиксируются в одной транзакции сразу после инициализации платежа; повторный запрос восстанавливает пропавшую ссылку у провайдера.
- Усилена надёжность освобождения PostgreSQL advisory lock в billing worker: cleanup выполняется в отдельном коротком контексте и фиксируется в логах, чтобы lock не зависал при отмене родительского контекста.

## 2026-06-20

### Добавлено
- Добавлена документация по запуску локального нагрузочного тестирования read endpoint'ов через `vegeta`.
- Добавлен двухтерминальный запуск perf-стенда: отдельно backend с живыми логами, отдельно нагрузочный тест.
- Добавлены режимы автоматического подбора RPS: `sustainable` (max RPS при p95 < 500 мс и 100 % success) и `breakdown` (max RPS до достижения 10 % ошибок).
- Добавлены `make perf-sustainable` и `make perf-breakdown`.
- Добавлена диагностика узкого места после нагрузочных запусков: backend, PostgreSQL, генератор или неизвестная причина.
- Добавлена локальная диагностика пула соединений backend для нагрузочных прогонов.
- Добавлены предупреждения о конкуренции за backend pool и признак нестабильной границы в отчётах нагрузочного тестирования.
- Добавлена локальная диагностика медленных обращений к базе данных во время нагрузочных прогонов.

### Исправлено
- Диагностические логи базы данных теперь показывают понятные названия операций вместо служебного placeholder.
- В billing убраны внешние вызовы платёжного провайдера изнутри транзакций базы данных: автопродление фиксирует pending-платёж в отдельной транзакции, а уже потом обращается к провайдеру. При сбое подписка корректно переходит в grace-период.
- Исправлена утечка транзакции в `changeTariffUpgrade` при ошибке инициализации платежа у провайдера.
- Просмотр договоров аренды больше не изменяет их статус в базе данных; статус рассчитывается при отображении.
- Просмотр списка периодических операций и карточки операции больше не создаёт записи в базе; горизонт операций обновляется только при создании, изменении и возобновлении.
- Усилены проверки целостности данных на уровне базы: у одного объекта не может быть двух одновременно открытых договоров аренды, день платежа по периодической операции ограничен диапазоном 1–31, а мягко удалённые операции не попадают в выборки дат и повторных удалений.
- Проверки лимита активных объектов и открытых договоров аренды перенесены внутрь транзакций и защищены блокировками строк, чтобы избежать состояния гонки при параллельных запросах.
- Усилены меры безопасности: фейковый SMS-отправитель доступен только в локальной и dev-среде, отсутствие ключа шифрования запрещено с реальным платёжным провайдером, отсутствие APP_ENV приводит к ошибке запуска, а в problem-ответах больше не возвращаются внутренние детали ошибок. Добавлены HSTS-заголовки, проверка формата X-Request-ID, очистка просроченных сессионных cookie и корректная установка срока жизни cookie.
- Исправлена массовая вставка операций аренды: теперь используется быстрый COPY, а ошибки при загрузке не скрываются.
- Устранена возможная паника в `SubscriptionRepository.WithTx` при передаче неподдерживаемого типа транзакции.

### Изменено
- Улучшены observability и производительность платформы: логирование успешных запросов настраивается через env, статус подписки кэшируется в рамках одного запроса, rate limiter стал шардированным, сессия не загружается для публичных endpoint'ов, фоновые воркеры корректно завершаются при остановке, очистка старых данных выполняется пакетами, а пул соединений PostgreSQL стал настраиваемым с таймаутами на запросы и простаивающие транзакции.
- `APP_ENV` теперь обязательна для запуска backend.
- Имя сессионной cookie изменено на `__Host-session_id` в защищённых окружениях.
- `COOKIE_SECURE=true` теперь используется по умолчанию во всех не-локальных окружениях.
- Код нагрузочного стенда приведён в соответствие с линтером.
- Для perf-режима настроен более устойчивый пул соединений к PostgreSQL с запасом для диагностики и служебных подключений.
- `perfvegeta` сохраняет все промежуточные прогоны в отчётах и явно помечает результат, если раньше backend'а упёрся генератор нагрузки.
- `perfvegeta` отдельно показывает лучшую успешную точку, первый отказ по SLO и первый отказ генератора нагрузки.
- `perfvegeta` делает паузу между пробами и подтверждает найденную sustainable-точку повторными прогонами.
- Базовая точка локального sustainable-прогона теперь сразу проверяет нагрузку 5000 RPS для `/me`.
- Локальный perf-профиль подключений к базе данных приведён к единому значению с запасом для диагностики.
- Локальные настройки пула базы данных и быстрых успешных access logs больше не задаются через env.
- Make-команды perf-стенда теперь запускаются из корня репозитория и по умолчанию проверяют `/me`.
- Seed для perf-стенда стал объёмнее: list endpoint'ы теперь читают реалистично заполненные списки.
- `GET /me` стал выполнять меньше повторных чтений при уже загруженной сессии.
- Проведён рефакторинг Go-идиом и perf-инструментов: `perfvegeta` разбит на пакеты, массовое создание операций использует быструю вставку в базу, устранено затенение логгера в `cmd/api`, ключи контекста переведены на типизированные сентинели, а диагностический HTTP-клиент нагрузочного стенда получил явные таймауты и лимиты соединений.

### Удалено
- Убран k6-оркестратор и k6-скрипты нагрузочного тестирования: генератор в Docker на локальной машине упирался в собственный потолок раньше бэкенда. Write endpoint'ы временно выведены из локального perf-покрытия.
- Убрана генерация фикстур для write endpoint'ов из perfseed: сейчас harness тестирует только read endpoint'ы.
- Убраны лишние perf-команды, которые дублировали запуск или относились к старому harness.
