Подписка пользователя определяет текущий тариф, лимит активных объектов и источник оплаты.

Платные подписки собственников оплачиваются через T-Кассу с автопродлением. Служебная подписка админа используется только для проверки тарифной логики и не участвует в списаниях.

## Оплата

* Пользователь выбирает тариф и период: месяц или год.
* Первая оплата проходит через T-Кассу.
* После успешной оплаты сервис сохраняет данные, необходимые для автопродления, согласно механике платежей по сохраненным реквизитам T-Кассы.
* Дальше подписка продлевается автоматически.

Эти правила применяются только к платной подписке собственника.

## Служебная подписка админа

Админ может назначить себе любой тариф в служебном режиме, чтобы проверить лимиты, автоархив, восстановление и readonly-поведение.

Служебная подписка:

* действует без срока, пока админ сам не сменит тариф;
* не проходит через T-Кассу;
* не создает списаний, платежных требований, автопродлений и льготного периода;
* не меняет цену платного тарифа и не делает платный тариф `0 ₽`;
* не может быть назначена собственнику.

Смена служебного тарифа применяется сразу и полностью. При понижении действуют обычные правила лимитов и тарифного автоархива. При повышении админ может вернуть объект из архива, если новый лимит позволяет.

## Смена платного тарифа

* Upgrade применяется сразу после успешной оплаты.
* Downgrade (включая платный даунгрейд на более дешёвый не-базовый тариф) применяется в конце уже оплаченного периода; списание выполняется биллинг-воркером в момент применения запланированной смены, а не сразу при вызове `ChangeTariff`.
* Отмена подписки отключает автопродление, но текущий тариф работает до конца оплаченного периода.

## Неуспешное списание

Этот раздел применяется только к платной подписке собственника.

Если автосписание не прошло:

1. начинается льготный период 7 дней;
2. пользователь сохраняет текущий тариф на время льготного периода;
3. если за 7 дней оплата не прошла, тариф понижается;
4. если объектов больше лимита нового тарифа, лишние объекты автоматически архивируются.

## Автоархив

При автоархиве система оставляет активными объекты в таком порядке:

* сначала объекты с открытой арендой;
* затем самые недавно обновленные объекты.

Внутри каждой группы объекты сортируются по `object.updated_at`, затем `object.created_at`, затем id по убыванию.

Если открытых аренд больше лимита нового тарифа, лишние объекты с открытыми арендами тоже архивируются. Это системное исключение: ручной архив объекта с открытой арендой по-прежнему запрещен.

При тарифном автоархиве:

* объект переводится в `Архив`;
* открытая аренда переводится в системный статус `Архив`;
* будущие неотредактированные операции удаляются;
* регулярные операции приостанавливаются и не создают новые операции, пока объект в архиве;
* будущие SMS останавливаются;
* история сохраняется.

Пока объект находится в архиве, финансовая история доступна только для просмотра. Создание, редактирование и удаление финансовых записей по архивному объекту недоступны.

## Восстановление после автоархива

После оплаты или повышения тарифа пользователь может вернуть объект из архива, если тарифный лимит позволяет.

При восстановлении:

* аренда возвращается в актуальный статус по датам;
* регулярные операции возобновляются с текущей даты;
* операции за период архива не создаются задним числом;
* ретроспективные SMS не отправляются.

## Админка

Админ видит:

* пользователя;
* текущий тариф;
* срок действия тарифа;
* платежный статус.

Админ может вручную назначить или продлить тариф для поддержки.

Для своего админского аккаунта админ может назначить только служебную подписку. Для собственников служебный режим недоступен: их платные тарифы остаются частью платежной логики.

Если подписка в режиме только для чтения (истёк льготный период или подписка отменена), пользователь может войти в кабинет только в режиме просмотра. Создание, редактирование и удаление данных недоступны, новые SMS не отправляются. После восстановления активной подписки ретроспективные SMS не догоняются.

Админ может отменить собственную служебную подписку для проверки readonly-режима. В этом случае режим просмотра применяется только к тестовому кабинету админа, а админские действия остаются доступны для восстановления подписки.

## Ограничения

* Возвраты не автоматизируются в MVP. Частичные возвраты не поддерживаются (все возвраты полные и инициируются только админом): внешнее уведомление провайдера о частичном возврате логируется и игнорируется без изменения состояния.
* Несколько способов оплаты не входят в MVP.
* Ручное продление вместо автопродления не входит в MVP.
