# MCP servers

Registry of the MCP servers this repo's agents rely on, where each is configured, and what to do when one is unavailable. Read before relying on an `mcp__<name>__*` tool; re-check here when a server is missing from the tool set. The serena/lean-ctx boundary line lives in the root `AGENTS.md` (Repo rules).

When a task depends on MCP tools, check that the server's tools are present in the agent tool set before relying on them. If a server is unavailable, tell the user (they can inspect `/mcp` themselves), state the fallback clearly, and continue with standard repository tools where safe.

## Servers

- `lean-ctx` — compressed reads and noisy-output compression (incl. file trees and shell output), semantic search by meaning, dependency/diff-impact graph, session intelligence. Use it for broad repository exploration, large or generated files, noisy command output, and repeated reads; before editing a file or relying on exact line-level behavior, read the relevant source in full or in precise raw ranges. Fallback when unavailable: native `Read`, `Grep`, `Glob`, `Bash`.
- `context7` — official library and framework documentation. Fallback when unavailable: official docs via `FetchURL` or `WebSearch`.
- `playwright` — browser automation and UI verification; one stdio server per session, so each session gets its own visible Chromium (headed by default, `--isolated` in-memory profile). All repository browser work — `/ui-walkthrough` live acceptance, headed spec runs, browser debugging — goes through it; the rule and the Browser Use ban: `docs/agents/parallel-dev.md`. Fallback when unavailable: stop and tell the user (Settings → MCP, restart the session), then manual inspection and build logs.
- `postgres` — read-only SQL over the local stacks' databases, main use `/ui-walkthrough` server-truth DB assertions. Only `pg_execute_query` is registered (`select`/`count`/`exists`); the rest of the server's tools are unregistered by the allowlist `.zcode/postgres-mcp.tools.json`, and a non-SELECT query is refused — DB checks verify, they never mutate. Binary: global `postgres-mcp` (`npm install -g @henkey/postgres-mcp-server@1.0.7`; npm latest is 1.0.7 — the GitHub README documents a 2.x with opt-in per-call-connection flags that is not published to npm; re-pin only after re-verifying the flag and tool surface). Wired per session from the committed workspace config `.zcode/config.json`; the connection string is passed **per call** by the agent (a live stack prints its port on raise — default 5436, worktree slots override), so no DSN lives in any config. Fallback when unavailable: `docker exec "<compose-project>-postgres-1" psql -U arenda -d arenda -tAc "<sql>"` — shelling into the container needs no host port, so it works for any slot.
- `figma` — Figma Dev Mode MCP server, **локальный** (`http://127.0.0.1:3845/mcp`, HTTP, без OAuth — авторизация это залогиненный desktop-клиент Figma). Включение: Figma desktop → файл Design → Dev Mode (`Shift-D`) → панель Inspect → «Enable desktop MCP server»; приложение должно быть запущено во время работы агента. Инструменты: `get_design_context` — React+Tailwind-представление фрейма, первый шаг вёрстки экрана из макета (скилл `figma-design-to-code`; вывод — референс, не код для вставки), `get_variable_defs` — токены выделения (наполняется по мере перевода файла на Variables: `.ops-figma-variables/checklist.md`), `get_screenshot`, `get_metadata`, `create_design_system_rules`. Официальный remote-сервер (`https://mcp.figma.com/mcp`) из ZCode недоступен: его OAuth не поддерживает динамическую регистрацию клиента — HTTP 403 (подключаются только клиенты с предзарегистрированным client_id, например Claude Code); PAT для него тоже не работает. Fallback when unavailable: `figma-context` + manual design references.
- `figma-context` — Framelink `figma-developer-mcp` (stdio, PAT-токен): `get_figma_data` — структура и flex-семантика ноды, точечные запросы по componentId; `download_figma_images` — массовый экспорт SVG-иконок канона и PNG-эталонов узлов для пиксельного дифа (`npm run figma:diff`, DESIGN.md §11). Роли серверов не пересекаются: контекст кода / токены / скриншот → `figma`; файловые экспорты → `figma-context`. Fallback when unavailable: manual design references.
- `serena` — code semantics for the whole stack (TS + Go): symbol navigation, references, rename, diagnostics, symbol-level editing. Pinned `serena-agent` 1.7.0 (`uv` + managed Python 3.13); committed project config `.serena/project.yml`, one project at the repo root. Serena is navigation and diagnostics, not a replacement for the apps' lint/build/test runs. If the `mcp__serena__*` tools are unavailable, stop and tell the user (they can inspect `/mcp`) — no silent substitution with text search or other tools.

## Config locations

The harness MCP config is the ZCode user config `~/.zcode/cli/config.json` (`mcp.servers`); `~/.kimi-code/mcp.json` is the Kimi Code equivalent (not used by the current ZCode-only setup); playwright and postgres additionally come from the committed repo workspace config `.zcode/config.json` (ZCode; auto-connects in every session and worktree). The `figma:*` skills (design-to-code, use, generate-*) come from the installed plugin `figma@claude-plugins-official`; the plugin also bundles the official remote server under the `figma` name, but the user config shadows it with the local Dev Mode server (same tool names). Config changes apply after a session restart.
