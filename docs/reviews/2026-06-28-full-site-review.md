# Полное ревью Arenda Platform: что реализовано и что осталось

**Дата:** 2026-06-28  
**Цель:** проверить, насколько текущая реализация бэкенда, фронтенда и тестов соответствует заявленному MVP, и выявить оставшиеся пробелы.

## Резюме

Система близка к MVP для собственника: авторизация, объекты, арендаторы, операции, регулярные операции, отчётность и подписка реализованы и связаны. Основные пробелы — это отсутствие UI для администратора, неполноценная работа с арендой (только создание, нет списка/карточки/редактирования), отсутствие управления SMS-напоминаниями и регулярными операциями «сериями», а также красный gate API E2E-покрытия и полное отсутствие UI-тестов.

## Бэкенд

### Что реализовано

Все ключевые домены MVP покрыты endpoint'ами:

| Домен | Endpoint'ы |
|---|---|
| Auth / пользователь | `POST /auth/phone/*`, `GET /me`, `PATCH /me`, `POST /me/phone/*`, `POST /auth/logout-all` |
| Объекты | CRUD, архивация, разархивация, фото, summary по операциям, подсказки адресов |
| Аренда | CRUD, завершение, возврат залога, reminders |
| Арендаторы | CRUD |
| Операции | CRUD по объекту и глобально, выполнение, удаление |
| Регулярные операции | CRUD, пауза/возобновление, reminders |
| Напоминания | CRUD, отвязка от операций/аренд |
| Отчёты | `GET /finance/report` (P&L) |
| Подписка / биллинг | Тарифы, подписка, автопродление, отмена, смена тарифа, способы оплаты, история платежей, T-Касса webhooks |
| Админ | Просмотр платежей, refund, sync |

### Замечания по бэкенду

- **Нет деструктивного удаления** для объектов, аренд, арендаторов и регулярных операций — вместо него архивация/завершение/пауза. Это соответствует MVP.
- **SMS-напоминания не имеют публичного endpoint'а отправки** — они создаются автоматически и рассылаются воркером.
- **Два технических долга:** номера телефонов хранятся в plaintext (`TODO` в `identity/adapters/postgres/repository.go`) и используется deprecated `chi/middleware.RealIP`.

### Критичные пробелы

| Пробел | Почему важно | Где в документации |
|---|---|---|
| **Нет `/leases` и `/leases/[id]`** | Аренда — ключевая сущность MVP; собственник не может посмотреть список аренд и детали конкретной аренды | `docs/service-functionality/leases/` |
| **Нет редактирования аренды** | `PATCH /leases/{id}` есть, но UI-страницы нет | `docs/service-functionality/leases/` |
| **Нет админ-панели** | В PRD/глоссарии админ должен видеть пользователей и управлять подписками | `docs/service-functionality/admin/` |
| **Нет управления SMS-напоминаниями** | Напоминания создаются только в wizard'е операции; нет списка/отмены/изменения | `docs/service-functionality/reminders/` |
| **Нет редактирования регулярной операции как серии** | В docs требуется правка одного экземпляра или серии с выбранной даты | `docs/entities/reguljarnaja-operacija.md` |
| **Корневая страница `/` — заглушка** | Показывает стартовый шаблон Next.js вместо лендинга или редиректа | — |
| **Нет клиентского auth guard** | Страницы кабинета полагаются на 401 от API; нет middleware/AuthGuard | — |

### Мелкие замечания

- В навигации нет отдельного пункта «Аренда».
- Сортировка в списке объектов по полям (name, status, nearest operation, updated) задокументирована, но явного UI-сортировки не видно.

## E2E и тестовое покрытие

### API E2E

- Набор Bruno-тестов в `tools/e2e/bruno/arenda-api-e2e/system-e2e/` покрывает happy path и негативные сценарии для auth, subscription, properties, tenants, leases, operations, recurring-operations, reminders, webhooks, readonly-recovery.
- **Coverage gate (`check-bruno-coverage.sh`) сейчас не проходит**, потому что ряд endpoint'ов не представлен в Bruno-коллекциях:
  - `DELETE /properties/{}/photos/{}`, `POST /properties/{}/photos`, `GET /properties/{}/leases`
  - `GET /dadata/suggestions/address`
  - `PATCH /me`, `POST /me/phone/change`, `POST /me/phone/send-code`
  - `POST /leases/{}/deposit-return`
  - `POST /auth/logout-all`
  - Admin endpoint'ы в E2E отсутствуют.
- Часть недавних проблем уже исправлена: добавлено обязательное поле `name` в create-запросы, починен `ORDER BY` в отчёте, перенесён порядок проверки списка операций.

### UI E2E

- **Браузерных тестов нет.** В `tools/screenshots/` есть Playwright-скрипты для создания скриншотов, но они не проверяют поведение.

## Приоритизированный список доработок

### P0 — блокирует полноценный MVP
1. **Страницы аренды:** `/leases`, `/leases/[id]`, `/leases/[id]/edit`.
2. **Админ-панель:** страница пользователей/подписок с действиями назначения/блокировки тарифа.
3. **Починить coverage gate:** добавить недостающие endpoint'ы в Bruno-коллекции (или в allow-list, если они намеренно не покрыты).

### P1 — сильно улучшает UX
4. **Управление SMS-напоминаниями:** список, отмена, изменение срока.
5. **Редактирование регулярной операции как серии:** UI для правки с выбранной даты вперёд.
6. **Auth guard на фронтенде:** middleware или AuthProvider с редиректом на `/login`.
7. **Корневая страница `/`:** лендинг или редирект в кабинет/логин.

### P2 — доработки и технический долг
8. Добавить UI E2E (Playwright) для критичных сценариев.
9. Сортировка списка объектов.
10. Шифрование телефонов (отложено ADR).
11. Заменить deprecated `chi/middleware.RealIP`.

## Вывод

Arenda Platform — это уже работающий кабинет собственника с реализованным финансовым ядром, подпиской и объектами. Для объявления MVP полноценным нужно закрыть UI аренды, админ-панель и привести E2E-coverage в зелёное состояние. Остальное — улучшения UX и технический долг.
