# ADR 0064: Гейтинг платных разделов по тарифу

Платные разделы кабинета (совместный доступ объекта, участники, история) закрываются для базового тарифа: бекенд отвечает 402 PaymentRequired с машинным кодом `tariff_required`, фронт-прокси редиректит на `/profile/tariff/change` до отрисовки страницы. Платность решается именем тарифа подписки — без таблицы «фича↔тариф»: единственный бесплатный план базовый, всё остальное платное, а страница выбора тарифа и так каноническое место апгрейда.

Ревизия #1313: раздел «Участники» гейтится частично — сама страница `/participants` открыта на basic как пустое состояние-апселл (D2 спеки «Совместный доступ»), вложенные маршруты и все API раздела остаются за гейтом.

## Context

Карта #997 вводит платные разделы: экраны доступны только платным тарифам (про, бизнес), базовый получает редирект на повышение. Решения владельца от 30.09 (лог гриллинга в комментарии карты):

- гейт при `subscription.tariff.name === 'basic'` или при отсутствии подписки (null → как basic); `grace`/`cancelled` на платном тарифе пропускаются — имя тарифа в подписке меняется только фактическим применением даунгрейда;
- гейтится только просмотр разделов; получить доступ (быть участником) на basic не запрещено, «Покинуть объект» работает;
- цель редиректа — `/profile/tariff/change`; контекстная плашка «Эта функция доступна на платных тарифах» (первоначально — по query `gate`) снесена решением владельца от 30.09: в дизайне экрана её нет;
- редирект на фронте — до отрисовки (proxy.ts уже зовёт `/me` на всех гейтуемых маршрутах и раньше выбрасывал тело), кнопки не прячутся; обход мимо UI ловит бекенд.

402 уже канон «нужен платный тариф» — лимит активных объектов отвечает им же (`property_handlers.go`).

## Decision

**Домен.** Платность — метод тарифа: `billing/domain.Tariff.IsPaid` (`Name != basic`; полярность «не базовый», чтобы будущий платный план из реестра имён покрывался по умолчанию). Статус подписки в решении не участвует: имя тарифа консервативнее статуса и не требует часов.

**Порт.** Consumer-side интерфейс `httpsupport.PaidSectionsGate` (`CanUsePaidFeatures`) рядом со своим потребителем — по ADR 0035, как `SubscriptionMutationChecker` readonly-гейта; с ревизии #1462 у адаптера второй consumer-side порт — `access/application.PaidSectionsGate` (см. ревизию). Адаптер `billing/adapters/http.PaidSectionsGate` читает подписку: нет подписки → false (basic), ошибка хранилища — наверх (middleware отвечает 500, гейт не fail-open).

**Бекенд-гейт.** `httpsupport.PaidSectionsMiddleware` поверх сгенерированных роутов через `r.With` — приём AdminOnlyMiddleware (генерированный OpenAPI-роутер не держит per-route middleware, chi берёт последнюю регистрацию). Группа экрана 1: `/properties/{propertyId}/access/*` — с ревизии #1462 снята с middleware, её гейт роль-осведомлённый и живёт в use-case'ах (см. ревизию). Группа экрана 2 (#999): все глобальные API-роуты `/participants*` — без исключений (группа пополняется новыми глобальными роутами раздела — так вошёл `DELETE /participants` «Отозвать доступ всем», #1310); с ревизии #1313 это не противоречит открытой странице раздела — на basic клиент не вызывает гейтованные чтения, список скрыт за апселлом. Группа экрана 3 (#1000): оба read-эндпойнта журнала `GET /history` и `GET /history/filters` — все страницы раздела и фильтр-шит обслуживаются этими двумя. Ответ: 402 + `httpsupport.ProblemWithCode(..., "tariff_required")`. Новая платная группа добавляется тем же приёмом.

**Фронт-гейт.** `proxy.ts` читает `subscription.tariff.name` из уже запрашиваемого `/me` и редиректит базовый/null-тариф с маршрутов платных разделов на `/profile/tariff/change` до отрисовки; сама эта страница не гейтится. Ревизия #1313: паттерн раздела «Участники» — только вложенные `/participants/.+` (поиск, приглашение, страница участника, права); точный `/participants` открыт на basic — экран рендерит пустое состояние-апселл «Участников нет» с CTA на `/profile/tariff/change` (D2), чтение списка выключает (`enabled` по тарифу), кебаб и пилюлю поиска прячет. Downgrade с живыми участниками — то же состояние: список скрыт до оплаты, данные не пропадают.

**Реестр гейтуемых поверхностей** — в коде: паттерны маршрутов в `shared/lib/paid-sections.ts` (фронт) и переопределения роутов в `httpserver/server.go` (бекенд). Таблица «фича↔тариф» в БД — не сейчас; вернуться при 3+ независимых платных фичах с разными тарифными порогами.

## Consequences

- (+) Обход фронта невозможен: API отвечает 402 с машинным кодом, который клиент отличает от generic-ошибок; редирект в прокси покрывает кнопки, глубокие ссылки, уведомления и закладки одним местом, без миганий. С ревизии #1463 для пер-объектного шаринга иначе: proxy-паттерн снят (proxy не знает роли читателя), кнопки и глубокие ссылки покрывает экранная разводка — клик без загрузки страницы, страховка после загрузки (см. ревизию).
- (+) Правило платности — один доменный метод; grace/cancelled корректны без часов, потому что опираются на имя тарифа, а не на статус.
- (−) Реестры гейтуемых поверхностей расходятся осознанно — с ревизии #1462 их три: фронт-паттерны (`shared/lib/paid-sections.ts`), screen-разводка (редиректы и апселл-состояния экранов) и бекенд-гейт в двух формах — middleware-оверрайды `httpserver/server.go` для групп целиком и use-case-шов access-контекста для роль-осведомлённой access-группы. Расхождение ловится walkthrough'ом нового экрана: гейт есть на одном регистре, а на другом поверхность открыта.
- (−) Владелец платного тарифа, пригласивший basic-пользователя, приводит его на редирект при открытии раздела; сам объект и «Покинуть объект» остаются доступны (решение Q2). С ревизии #1462 участник объекта на basic и раздел «Совместный доступ» читает — регистр бекенд-гейта различает владельца и участника там, где middleware различить их не может.

## Ревизия #1462: роль-осведомлённый гейт access-группы

Карта «Совместный доступ и История на базовом тарифе» (#1459, правило «пригласили — значит пользуется») снимает тарифный гейт с чтений участника объекта. Middleware не может этого сделать: у неё на момент запроса нет роли читателя на объекте, а вторая резолв-проходка (policy поверх middleware) — двойной резолв доступа. Гейт группы `/properties/{propertyId}/access/*` переезжает с роутов в access use-cases (ADR 0028), туда, где роль уже известна:

- **Шов.** `AccessService` получает consumer-side порт `application.PaidSectionsGate` (ADR 0035; биллинговый адаптер `billing/adapters/http.PaidSectionsGate` удовлетворяет ему наряду с `httpsupport.PaidSectionsGate` — один адаптер, два порта) и консультирует его ровно в двух местах: `ListMembers` — после `CanView`, только для `RoleOwner`; `requireManage` — после `CanManageMembers` (owner-only с D8 #1304), то есть тоже только для владельца. `InvitationService` и `ParticipantMutationService` ведут свои мутации через тот же `requireManage` — один шов закрывает все 10 мутирующих эндпоинтов участников. Список участников читается `GetMember`'ом (#1357) через тот же `ListMembers` — чтение строки автоматически под тем же гейтом.
- **Семантика.** Участник объекта (`full_access`/`viewer`) читает список и карту строки на любом тарифе; suspended-участник и посторонний получают прежний privacy-404, гейт не спрашивается; владелец на basic получает 402 `tariff_required` и в чтениях, и в мутациях — то же тело, что писала middleware (`httpsupport.ProblemWithCode(..., "tariff_required")`, маппинг `application.ErrTariffRequired` в обработчиках). Мутации участника отказывает ролевая политика (privacy-404), не тариф. Самовыход `DELETE .../access/members/self` — вне гейта, как и был. Ошибка хранилища гейта — наверх (500), гейт не fail-open; nil-гейт выключает проверку (конвенция опциональных зависимостей пакета; композиционный корень всегда передаёт адаптер).
- **Реестр бекенд-гейта.** Осталось две формы: middleware-оверрайды для групп целиком (`/participants*`, `/history*` — там роль не нужна, группа вся платная) и use-case-шов для access-группы (роль-осведомлённость). Композиционный пин middleware (httpserver) сужается на две оставшиеся группы; вердикты access-шва пинят тесты access-контекста (TDD на шве), wire-форму 402 — тесты обработчиков.

_Avoid_: «гейт в middleware для access-группы» (устарело), «двойной резолв роли» (антипаттерн, снятый этим решением).

## Ревизия #1463: screen-разводка шаринга — интерстишал вместо proxy-редиректа

Карта #1459 (решение владельца 15.10.2026): пер-объектный паттерн `/properties/{id}/participants…` снят с proxy-гейта — proxy не знает роли читателя, а участник объекта на basic разделом пользуется («пригласили — значит пользуется»; чтения открыты ревизией #1462). Владельца на basic разводит экран, источник решения один:

- **Шов.** `sharingGateRedirect(canManageMembers, isPaid)` в `shared/lib/paid-sections.ts` — владелец (`canManageMembers`, owner-only с D8 #1304) на basic идёт на интерстишал `/profile/tariff/sharing` («Совместный доступ недоступен», #1470); участник — null, странице всё. `isPaid` — optimistic-умолчание канона экранов (`usePaidTariff`, features/subscription): подписка не загружена/нет — платный; истиной остаётся бекенд-гейт.
- **Входы.** Клик «Совместного доступа» на экране объекта (кебаб и секция «Управление») — `router.push` интерстишала без загрузки страницы; страховка от глубоких ссылок, уведомлений и закладок — клиентский гейт-лейаут префикса `/properties/{id}/participants…` (список, приглашение, права) — `router.replace` на тот же интерстишал после загрузки роли и тарифа. Пункт «Совместного доступа» в кебабе виден всем (решение D15 #1312 «платная функция не приманивает» снято #1464, владелец 15.10.2026) — единственным местом прятания был кебаб, секция «Управление» не прятала; расхождение снято в пользу видимого пункта с разводкой внутри клика.
- **Реестр.** Паттерн `/properties/{id}/participants…` уходит из proxy-реестра; ретаргет оставшихся sharing-поверхностей (`/participants/.+`, `/history`) с `/profile/tariff/change` на интерстишал и сам экран — тикет #1470.

_Avoid_: «пер-объектный гейт в proxy» (устарело), «страховка по тарифу без роли» — решение разводки знает обе величины, у proxy тарифной величины без роли нет смысла.
