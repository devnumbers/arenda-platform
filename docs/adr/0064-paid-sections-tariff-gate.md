# ADR 0064: Гейтинг платных разделов по тарифу

Платные разделы кабинета (совместный доступ объекта, участники, история) закрываются для базового тарифа: бекенд отвечает 402 PaymentRequired с машинным кодом `tariff_required`, фронт-прокси редиректит на `/profile/tariff/change` до отрисовки страницы. Платность решается именем тарифа подписки — без таблицы «фича↔тариф»: единственный бесплатный план базовый, всё остальное платное, а страница выбора тарифа и так каноническое место апгрейда.

## Context

Карта #997 вводит платные разделы: экраны доступны только платным тарифам (про, бизнес), базовый получает редирект на повышение. Решения владельца от 30.09 (лог гриллинга в комментарии карты):

- гейт при `subscription.tariff.name === 'basic'` или при отсутствии подписки (null → как basic); `grace`/`cancelled` на платном тарифе пропускаются — имя тарифа в подписке меняется только фактическим применением даунгрейда;
- гейтится только просмотр разделов; получить доступ (быть участником) на basic не запрещено, «Покинуть объект» работает;
- цель редиректа — `/profile/tariff/change` с query-контекстом и плашкой «Эта функция доступна на платных тарифах»;
- редирект на фронте — до отрисовки (proxy.ts уже зовёт `/me` на всех гейтуемых маршрутах и раньше выбрасывал тело), кнопки не прячутся; обход мимо UI ловит бекенд.

402 уже канон «нужен платный тариф» — лимит активных объектов отвечает им же (`property_handlers.go`).

## Decision

**Домен.** Платность — метод тарифа: `billing/domain.Tariff.IsPaid` (`Name != basic`; полярность «не базовый», чтобы будущий платный план из реестра имён покрывался по умолчанию). Статус подписки в решении не участвует: имя тарифа консервативнее статуса и не требует часов.

**Порт.** Consumer-side интерфейс `httpsupport.PaidSectionsGate` (`CanUsePaidFeatures`) рядом со своим единственным потребителем — по ADR 0035, как `SubscriptionMutationChecker` readonly-гейта. Адаптер `billing/adapters/http.PaidSectionsGate` читает подписку: нет подписки → false (basic), ошибка хранилища — наверх (middleware отвечает 500, гейт не fail-open).

**Бекенд-гейт.** `httpsupport.PaidSectionsMiddleware` поверх сгенерированных роутов через `r.With` — приём AdminOnlyMiddleware (генерированный OpenAPI-роутер не держит per-route middleware, chi берёт последнюю регистрацию). Группа экрана 1: `/properties/{propertyId}/access/*`; исключение — `DELETE /properties/{propertyId}/access/members/self`: «Покинуть объект» живёт на детальной объекта, вне платных разделов. Группа экрана 2 (#999): все шесть глобальных роутов `/participants*` — без исключений, все их потребители живут внутри гейтуемого раздела; глобальная форма приглашения объекта (шаг визарда) отправляет `POST /participants/invite` изнутри раздела и закрыта им же. Ответ: 402 + `httpsupport.ProblemWithCode(..., "tariff_required")`. Следующие экраны карты добавляют свои группы тем же приёмом (`/history*`).

**Фронт-гейт.** `proxy.ts` читает `subscription.tariff.name` из уже запрашиваемого `/me` и редиректит базовый/null-тариф с маршрутов платных разделов на `/profile/tariff/change?gate=<раздел>` до отрисовки; на странице смены тарифа по `gate` показывается лёгкая плашка. Страница `/profile/tariff/change` сама не гейтится.

**Реестр гейтуемых поверхностей** — в коде: паттерны маршрутов в `shared/lib/paid-sections.ts` (фронт) и переопределения роутов в `httpserver/server.go` (бекенд). Таблица «фича↔тариф» в БД — не сейчас; вернуться при 3+ независимых платных фичах с разными тарифными порогами.

## Consequences

- (+) Обход фронта невозможен: API отвечает 402 с машинным кодом, который клиент отличает от generic-ошибок; редирект в прокси покрывает кнопки, глубокие ссылки, уведомления и закладки одним местом, без миганий.
- (+) Правило платности — один доменный метод; grace/cancelled корректны без часов, потому что опираются на имя тарифа, а не на статус.
- (−) Два реестра (фронт-паттерны и бекенд-оверрайды) надо менять парно — расхождение ловится walkthrough'ом нового экрана: фронт-гейт есть, а API отвечает 200, или наоборот.
- (−) Владелец платного тарифа, пригласивший basic-пользователя, приводит его на редирект при открытии раздела; сам объект и «Покинуть объект» остаются доступны (решение Q2).
