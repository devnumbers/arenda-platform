# ADR 0067: Email-only логин — телефон покидает Identity

## Status

Accepted (grilling ticket [#1527](https://github.com/devnumbers/arenda-platform/issues/1527), карта [#1525](https://github.com/devnumbers/arenda-platform/issues/1525), решение владельца от 18.10.2026); **supersedes ADR 0009** (шифрование номеров телефона — шифруемого идентификатора больше нет) **и ADR 0015** (вход «телефон → email → код» — поток заменён входом по одному адресу). ADR 0044 (удаление SMS-канала) не затронут: он решает судьбу канала доставки, а не идентификатора; фраза его Context «the phone is the account identifier» перекрыта настоящим ADR.

## Context

Телефон был логином с первой миграции (000001: `users.phone NOT NULL UNIQUE`, окно попыток на номере), email — адресом доставки кода (ADR 0015: `/auth/send` без email ищет адрес по номеру). SMS-канал удалён (ADR 0044), номера шифруются детерминированно на записи (ADR 0009, миграция 000048), ключ кода — триплет `phone + COALESCE(email,'') + purpose`. Решения владельца (карта #1525, 18.10.2026): телефон вырезается из Identity/аутентификации/профиля/админки полностью, без заделов под будущий SMS; модель входа — единый поток «email → 6-значный код», вход = регистрация (новый адрес создаёт аккаунт, код подтверждает владение); прод-пользователей нет, БД сбрасываема — обратная совместимость миграций не требуется; лендинг не трогается. Протокол смены email двумя кодами (#721) и сессии (ADR 0056) сохраняются как есть.

Фактура по research [#1526](https://github.com/devnumbers/arenda-platform/issues/1526) (OWASP/NIST/system-design-primer, `research/email-only-auth-best-practices.md` на ветке `research/email-auth`): ключ окна попыток — логин-идентификатор в паре с IP («both the IP and the account»), не суррогатный `user_id` — несуществующие адреса не резолвятся в аккаунт; шифрование идентификатора не предписано, нормализация — каноническая форма без вырезания плюс-тегов.

## Decision

**Email — канонический идентификатор.** `users.email` — `NOT NULL`, уникальность без регистра обеспечивает существующий LOWER-индекс (000049); колонки `users.phone`, `users.phone_encrypted` дропаются. Каноническая форма адреса — обрезка пробелов и нижний регистр; плюс-теги и точки не вырезаются.

**Схема (append-only миграция 000162, правило репо — прецеденты 000064/000108/000112: даже при сбрасываемой БД история решений читается по журналу миграций, старые файлы не переписываются):**

- `login_codes`: триплет `(phone, COALESCE(email,''), purpose)` схлопывается в пару `(email, purpose)` — `email SET NOT NULL`, дроп `phone`, `phone_encrypted` и CHECK `login_codes_phone_or_email`, уникальный частичный индекс пересоздаётся как `(email, purpose) WHERE used = false`; `user_id` остаётся nullable (код на новый адрес живёт до создания аккаунта); инвариант срока действия (000110) остаётся.
- `login_attempts`: ключ окна — канонический email (`NOT NULL` + уникальный индекс вместо `phone UNIQUE`); `user_id` дропается — после удаления протокола смены телефона у него не остаётся читателей; CHECK-инварианты 000103 (`failures >= 0`, порядок времён) остаются без изменений. IP-слой троттлинга (жёсткий на issuance, мягкий на verify — по research #1526) — надстройка тикета #1528, в схему этой миграцией не входит.

**Протокол смены телефона исчезает целиком:** `/me/phone/send-code` и `/me/phone/change` (openapi + генерат), `phone_change_service` и порт `PhoneChanger`, цель кода `phone_change`, шаблоны `phone_change_code`/`phone_change_done`, audit-типы `auth.phone_changed`/`auth.phone_change_failed` и kind письма `phone_changed`, лимиты `RATE_LIMIT_PHONE_CHANGE_*`. Имена остальных лимитов остаются: после удаления телефона `RATE_LIMIT_EMAIL_SEND_PER_HOUR`/`_VERIFY_PER_15MIN` называют ровно то, что ограничивают (email-поток входа).

**Шифрование телефонов удаляется** (`phone_crypto.go`, детерминированные фильтры по телефону в identity и админке, админ-фильтр переезжает на существующий поиск по email). Платформа `encryption.Encryptor` и `ENCRYPTION_KEY` остаются — их основной потребитель не телефонный: карты платёжных методов (billing `payment_method_repository`).

**Кросс-контекстные читатели `users.phone` переезжают на email** (админские вью и фильтры пользователей, объектов и платежей — `OwnerPhone`/`UserPhone` → `OwnerEmail`/`UserEmail`, выборка участников истории, `AccessEventUser` в notifications). Детализация API-контракта — тикет #1528; экраны админки — #1532.

## Consequences

- Потеря доступа к почтовому ящику означает потерю доступа к аккаунту: восстановление — только ручная операция поддержки через админку.
- Параметры безпарольного входа (длина кода, попытки на код до аннулирования, resend-кулдауны, IP-слой, анти-enumeration поведение `/auth/send`) фиксируются тикетом #1528 по выводам research #1526 — эта миграция их не меняет.
- ADR 0009 и ADR 0015 помечены superseded; глоссарий Identity догнан за решением (статьи «Телефон», «Смена телефона» удалены; окно попыток, триплет, цели кода переписаны на email).
- Ключ кода, троттл и лимиты формулируются по паре email+цель; лимит инициатора считает только операции смены email.
- Env-ключи `RATE_LIMIT_PHONE_CHANGE_*` выбрасываются из окружений деплоя; `ENCRYPTION_KEY` остаётся обязательным.
