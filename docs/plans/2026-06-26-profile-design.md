# Дизайн: страницы профиля

**Дата:** 2026-06-26  
**Статус:** утверждено (подход B — вертикальные срезы)  
**Связанные файлы:** `apps/frontend/app/(cabinet)/profile/file.md`, `docs/entities/polzovatel.md`, `docs/service-functionality/vxod-registracija.md`

## 1. Контекст

### Фронтенд
- Next.js 16 App Router, FSD-архитектура, Tailwind + HeroUI + собственный UI-kit (`shared/ui`).
- Данные загружаются через `@tanstack/react-query`, клиент `shared/api/client.ts`, типы генерируются из OpenAPI.
- Формы пишутся вручную на `useState` (нет react-hook-form/zod).
- Маршрут `/profile` уже есть, но страница — заглушка `<h1>Профиль</h1>`.
- Есть `useMe()` → `GET /me`, `useLogout()` → `POST /auth/logout`, биллинг-хуки (`useTariffs`, `useSubscription`, `usePaymentMethods`, …).

### Бэкенд
- `GET /me` отдаёт `id`, `phone`, `role`, `name`, `surname`, `patronymic`, `email`, `subscription`.
- Биллинг уже реализован через T-Kassa: тарифы, подписка, смена тарифа, способы оплаты, операции, авто-продление, отмена.
- **Нет** endpoint'ов для изменения пользовательских данных, телефона и email.
- Сессии — cookie `session_id`, sliding expiration 7/30 дней, `logout` / `logout-all` уже есть.

### Домен
- Пользователь = владелец (`owner`), вход по телефону + SMS.
- Обязательные поля: телефон, роль. Опциональные: имя, фамилия, отчество, email.
- Телефон — логин.

## 2. Требования

1. **Объём:** все страницы из `apps/frontend/app/(cabinet)/profile/file.md`.
2. **Смена телефона:** подтверждение нового номера SMS-кодом, текущая сессия сохраняется, остальные сессии сбрасываются.
3. **Email:** сохраняется без подтверждения (валидация формата).
4. **Поддержка:** статическая страница с контактами и ссылками.
5. **Информация:** статические markdown-страницы для политики конфиденциальности и пользовательского соглашения.
6. **Оплата:** реальная интеграция с T-Kassa, уже реализована на бэкенде.
7. **Дизайн:** в едином стиле приложения, макетов Figma нет.
8. **Безопасность:** дополнительные меры не требуются.
9. **Дополнительно:** удаление аккаунта, уведомления, язык/тема — не нужны.

## 4. Выбранный подход

**Подход B — вертикальные срезы.** Реализуем каждый пользовательский сценарий «от экрана до БД» полностью, прежде чем браться за следующий.

Порядок реализации:
1. Просмотр профиля + выход.
2. Редактирование личных данных (ФИО/email).
3. Смена телефона.
4. Тариф / смена тарифа.
5. Способы оплаты.
6. История операций.
7. Поддержка + информационные страницы.

## 5. Бэкенд

### 5.1. Новые endpoint'ы

#### `PATCH /me`
Обновляет поля текущего пользователя.

**Тело запроса:**
```yaml
name: string | null
surname: string | null
patronymic: string | null
email: string | null   # валидация email-формата
```

**Ответ:** `MeResponse`.

**Логика:**
- Валидация email.
- Трим строк, null-пустая строка приводится к null.
- Обновление `updated_at`.

#### `POST /me/phone/send-code`
Отправляет SMS-код на новый номер телефона.

**Тело запроса:**
```yaml
phone: string   # +7XXXXXXXXXX
```

**Логика:**
- Проверить, что номер отличен от текущего.
- Проверить, что номер не занят другим пользователем.
- Использовать ту же логику лимитов, что и `/auth/phone/send`: 1 SMS в минуту, блокировка после 5 неудачных попыток за 30 мин, код действителен 5 мин.
- Сохранить код в таблице `sms_codes` с отметкой `purpose=phone_change` и `user_id`.

#### `POST /me/phone/change`
Подтверждает новый номер телефона.

**Тело запроса:**
```yaml
phone: string
code: string   # 6 цифр
```

**Логика:**
- Проверить код по `sms_codes` (purpose=phone_change, user_id).
- Обновить `users.phone`.
- Удалить использованный код.
- Аннулировать все сессии пользователя кроме текущей.
- Вернуть `MeResponse`.

### 5.2. Изменения в схеме/коде

- Добавить поле `purpose` (или отдельную таблицу) в `sms_codes` для разделения логина и смены телефона.
- Добавить методы `UpdateUser`, `GetUserByPhone` в identity-репозиторий.
- Добавить метод удаления сессий по user_id с исключением текущей.
- Обновить `openapi.yaml`, сгенерировать типы.

## 6. Фронтенд

### 6.1. Общие решения
- Каждый экран — отдельный `page.tsx` в `app/(cabinet)/profile/`.

## 7. Обработка ошибок

- 400/422 — текст ошибки под полем или в тосте.
- 401 — редирект на `/login`.
- 409 — «Этот номер уже привязан к другому аккаунту».
- 429 — показать оставшееся время.
- 500 — тост «Произошла ошибка, попробуйте позже».

## 8. Тестирование

- Бэкенд: unit-тесты сервиса смены телефона и обновления профиля; интеграционные тесты хендлеров.
