# CONTEXT.md

This file is a domain glossary. It intentionally avoids implementation details.

## Собственник / Owner

Пользователь сервиса, который управляет объектами, арендами, операциями, регулярными операциями, SMS-настройками и подпиской.

## Админ / Admin

Внутренний пользователь сервиса для поддержки. Админ не ведет объекты и финансы за собственника, но может вести собственные тестовые данные для проверки тарифной логики.

## Объект / Property

Минимальная сдаваемая единица, по которой можно заключить аренду и вести денежные записи.

## Арендатор / Tenant Contact

Необязательный контакт собственника. В MVP арендатор не является пользователем сервиса.

## Аренда / Lease

Учетная запись условий аренды по одному объекту.

## Открытая аренда / Open Lease

Аренда в статусе `Ожидает начала`, `Активная` или `Требует действия`.

## Операция / Operation

Денежная запись по объекту: доход или расход на прошлую, текущую или будущую дату. Операция проходит через статусы: запланирована (`pending`), просрочена (`overdue`), не подтверждена (`unconfirmed`), выполнена (`paid` для расхода, `received` для дохода).

## Запланированная операция / Pending Operation

Операция, созданная в статусе `pending` и ещё не выполненная.

## Просроченная операция / Overdue Operation

Запланированная операция, дата которой наступила, а статус так и не стал выполненным.

## Неподтверждённая операция / Unconfirmed Operation

Операция, созданная задним числом (датой в прошлом) в статусе `unconfirmed`. Требует явного подтверждения собственником и никогда не переходит в `overdue` автоматически.

## Выполненная операция / Completed Operation

Операция, отмеченная собственником как выполненная: `paid` (расход) или `received` (доход).

## Регулярная операция / Recurring Operation

Шаблон повторяющейся денежной записи по объекту. Регулярная операция создает обычные операции на ограниченный горизонт вперед.

## Категория дохода / Income Category

Фиксированный вид доходной операции по объекту: арендная плата или прочий доход.

## Категория расхода / Expense Category

Фиксированный вид расходной операции по объекту: ЖКХ, ремонт, налог или прочее.

## Оплата подписки / Subscription Payment

Денежное событие оплаты тарифа собственника через платежного провайдера. Оплата подписки относится к подписке и не является финансовой операцией по объекту.

## Платежи / Payments Section

Пользовательский раздел интерфейса для операций и регулярных операций по объектам. Это не отдельная доменная сущность и не оплата подписки.

## Залог / Deposit

Справочная сумма обеспечения в условиях аренды. В MVP залог не является отдельной финансовой сущностью.

## Активный объект / Active Property

Неархивный объект. Активные объекты считаются в тарифных лимитах.

## Архивный объект / Archived Property

Объект, скрытый из активных списков и доступный только для просмотра истории.

## Удаление объекта / Property Deletion

Безвозвратное удаление объекта в одном из двух режимов: каскадное (`cascade`) — вместе со всеми арендами, операциями, регулярными операциями и напоминаниями; с отвязкой (`detach`) — удаляется только объект, а его данные сохраняются без привязки к нему (`property_id = null`), при этом регулярные операции приостанавливаются. Фотографии удаляются в обоих режимах. Запрещено при открытой аренде. См. ADR 0025 (docs/adr/0025-property-deletion-modes.md).

## Тариф / Tariff Plan

План подписки, который задает лимит активных объектов и стоимость.

## Подписка пользователя / User Subscription

Состояние тарифа пользователя. Подписка может быть платной для собственника или служебной для админа.

## Способ оплаты / Payment Method

Сохраненный платежный инструмент пользователя (например, привязанная карта). Для каждого пользователя может быть несколько способов оплаты, но активным — только один. Способ оплаты используется для автопродления подписки. Для повторных списаний в нём хранится провайдерский токен автоплатежа, зашифрованный в покое, и идентификатор карты у провайдера.

## Автопродление / Auto Renew

Настройка подписки, при которой по окончании оплаченного периода списывается плата за тот же тариф и период продлевается.

## Статусы подписки / Subscription Status

- `active` — подписка оплачена или бесплатная, изменения данных разрешены.
- `grace` — не удалось списать платеж за продление, отсрочка для повторной попытки или смены способа оплаты; изменения данных временно разрешены.
- `cancelled` — подписка отменена пользователем; автопродление отключено, но изменения данных доступны до конца оплаченного периода, восстановление возможно через оплату тарифа.

## Апгрейд / Upgrade

Смена тарифа на более дорогой. Выполняется сразу после успешной оплаты, стоимость рассчитывается по полной цене нового тарифа, срок действия отсчитывается от момента оплаты.

## Даунгрейд / Downgrade

Смена тарифа на более дешевый. Не требует немедленной оплаты, вступает в силу в конце уже оплаченного периода. При даунгрейде, если количество активных объектов превышает лимит нового тарифа, система архивирует лишние объекты.

## Льготный период / Grace Period

Срок после неудачного автосписания, в течение которого подписка остается в статусе `grace` и пользователь может обновить способ оплаты. По истечении льготного периода подписка переходит на базовый тариф, а избыточные объекты автоматически архивируются.

## Настройки уведомлений / Notification Preferences

Пользовательская настройка отправки напоминаний по типам. Управляется собственником в профиле, на странице «Мои данные», секция «Уведомления». См. ADR 0022 (docs/adr/0022-notification-preferences.md).

## Разрешение на тип напоминания / Reminder Type Permission

Флаг разрешения отправки для одного типа напоминаний: напоминание об операции, просроченная операция, окончание аренды, аренда требует действия. Работает по модели opt-out: по умолчанию все типы разрешены. Отозванный тип не отправляется; напоминание, пропущенное из-за запрета, получает терминальный статус `skipped`. Разрешение привязано к типу и действует на все каналы отправки.

## Онбординг-попап / Onboarding Popup

Модальное окно, показываемое пользователю ровно один раз при входе в кабинет. Первый такой попап — о напоминаниях (ключ `reminders_onboarding`): текст, чекбоксы типов напоминаний и подсказка о дальнейшей настройке в «Моих данных». Закрывается только кнопкой «Сохранить». См. ADR 0023 (docs/adr/0023-popup-views.md).

## Просмотр попапа / Popup View

Серверный маркер того, что пользователь видел конкретный попап: запись в `user_popup_views` по паре (пользователь, ключ попапа). Гарантирует показ ровно один раз на всех устройствах. См. ADR 0023 (docs/adr/0023-popup-views.md).

## Журнал действий / Audit Log

Персистентный журнал «кто, когда, что сделал»: действия пользователей, админов и системы. Записи хранятся в таблице `audit_log` и пишутся в транзакции бизнес-операции. Просмотр — в админке: раздел «Журнал действий» и вкладка у пользователя. См. ADR 0020 (docs/adr/0020-audit-log.md).

## CC (Card Credentials)

Платёж по введённым карточным данным; родительский платёж CC/COF-связки.

## COF (Credentials on File)

Платёж по сохранённым реквизитам (RebillId).

## CIT (Customer-Initiated Transaction)

Операция, инициированная покупателем.

## MIT (Merchant-Initiated Transaction)

Операция, инициированная мерчантом (например, автопродление подписки).

## RebillId

Идентификатор сохранённых реквизитов в Т-Кассе, выдаётся после родительского платежа с Recurrent=Y.

## OperationInitiatorType

Тип COF-операции в запросе Init (поле DATA): 0/1/2/R/I/D/N, см. ADR 0017 (docs/adr/0017-tkassa-acquiring-contract.md).

## CheckType

Тип проверки карты при привязке в Т-Кассе: `NO`, `HOLD`, `3DS`, `3DSHOLD`, см. ADR 0017 (docs/adr/0017-tkassa-acquiring-contract.md).

## PaymentId

Идентификатор платежа в Т-Кассе, выдаётся в ответе `Init`.

## RequestKey

Идентификатор запроса на привязку карты в Т-Кассе, возвращается `AddCard` и приходит в add-card webhook.

## NotificationURL

URL мерчанта для webhook-уведомлений Т-Кассы о статусах платежа.
