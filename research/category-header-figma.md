## 1. Заголовок (главное изменение)

На кадре 1049:34768 заголовок — инстанс компонента **Heading #699:8717**
(сет Heading 699:8718), у которого текст заголовка переопределён на текстовый
стиль **Service/Heading/H1/600**:

| Параметр | Значение | Токен/класс проекта |
|---|---|---|
| Шрифт | Onest | `--font-sans` (Onest) |
| Начертание | SemiBold, вес **600** | `font-semibold` |
| Размер | **28px** | `text-[28px]` (эквивалент `text-2xl`: в `globals.css` `--text-2xl: 1.75rem`, `--text-2xl--line-height: 2rem` = 28/32) |
| Интерлиньяж | **32px** | `leading-8` |
| Letter-spacing | не задан (0) | — |
| Цвет | **#171A1C** | `text-content` = `--color-content` → `--dl-text-primary: #171a1c` (tokens.css) |
| Выравнивание | влево | — |

**Да, это тот же H1 28/32, что на логине и остальных новых экранах**: в коде
уже есть канонический паттерн `text-[28px] font-semibold leading-8 text-content`
(`features/auth/ui/step-chrome.tsx:24`, `shared/ui/design/hub-title.tsx:18`,
`widgets/rentals/ui/wizard-chrome.tsx:46`).

Важно: сам компонент Heading (699:8717) по умолчанию остался на
**Service/Heading/H3/600 = 20/24 SemiBold** — H1/600 это переопределение
именно на кадре выбора категории (owner: «Там обновился хедер»). Комментарий в
`wizard-chrome.tsx` («Heading 699:8717 — H3 20/24») больше не описывает этот
кадр.

**«Без описания» — подтверждено**: у инстанса
`componentProperties={"Show Description":false,"Show Subtitle":false}` — ни
подзаголовка «Выберите категорию», ни описания, ни стрелки
(`Show Arrow":false`). Текст заголовка на кадре — **«Выберите категорию
платежа»** (в коде сейчас «Категория платежа»).

### Отступы заголовочного блока

Геометрия блока не изменилась (у компонента и инстанса одинаковая):

- паддинг инстанса: **24px сверху, 24px по бокам, 0 снизу** (`pt-6 px-6`);
- внутри инстанса gap 8px между заголовком и (скрытым) подзаголовком (`gap-2`);
- кадр 1049:34768 несёт `padding-top: 72px` под плавающий TopNav (44px) →
  зазор навбар→контент 28px, итого **навбар→заголовок = 28+24 = 52px** —
  как зафиксировано комментарием в `payment-create-wizard-flow.tsx:170-172`;
- **заголовок→список = 24px** (контентный фрейм #1049:35268, `gap: 24px`);
- нижний отступ страницы — **136px** под плавающую панель (Page Content
  #1049:34832, `padding: 0px 0px 136px`) — совпадает с `PageContent`
  (`pb-[136px]`).

## 4. Экран ПРАВКИ платежа — есть ли вариант с H1/600?

В файле найден канон правки — кадр **«Mobile» #781:12299** (именно он
указан комментарием в `payment-edit-screen.tsx:465`): страница выбора
категории из модалки правки. Его заголовок:

- тот же компонент **Heading #699:8717**, но **без переопределения в H1**:
  текст заголовка «Какой платеж» в стиле **Service/Heading/H3/600 = 20/24
  SemiBold**, и **подзаголовок показан** («Выберите категорию или создайте
  свою», 14/16, #6F787C). Геометрия та же (24/24/0, gap 8, кадр
  `72px 0px 128px`, gap 24 до списка).
- шапка — старый компонент **TopNav Variant=Text #651:5607** с центрированным
  текстом «Выберите категорию» (не новый Top Navigation со чипом).

Вывод: **обновление до H1/600 в макетах коснулось только шага визарда
(1049:34768)**; отдельного обновлённого макета инлайн-страницы правки с
H1/600 в файле не найдено. Код правки (`payment-edit-screen.tsx:468-522`)
сейчас вообще без Heading-блока — `TopNavTitle «Выбор категории»`
(`text-base font-medium` = 16/18 Medium, `shared/ui/design/top-nav.tsx:346`),
что расходится и с 781:12299 (там большой заголовок + подзаголовок). Переводить
правку на H1/600 макет не требует; если владелец захочет единообразия —
это отдельное решение (сейчас: правка = TopNavTitle, шаг визарда = H1/600).

Поиск применений Heading/H1 по файлу средствами API (без полного экспорта)
ограничен; проверены оба канонических кадра выбора категории (1049:34768 и
781:12299) — стили зафиксированы выше по фактическому содержимому узлов.

## 5. Готовый маппинг на дизайн-систему

Заголовок шага (вместо текущего `WizardHeading` 20/24 + подзаголовок):

```tsx
{/* H1/600 28/32 — Service/Heading/H1/600, кадр 1049:34768; паттерн как
    в rentals/wizard-chrome и step-chrome (логин) */}
<div className="flex flex-col px-6 pt-6">
  <h1 className="m-0 text-[28px] font-semibold leading-8 text-content">
    Выберите категорию платежа
  </h1>
</div>
```

Эквивалент одной строкой: `text-2xl font-semibold text-content` — в теме
проекта `--text-2xl` уже 28/32; в коде принята явная форма
`text-[28px] … leading-8` — ей и следовать.

Остальное:

- отступы блока — без изменений: `px-6 pt-6` (= 24/24/0), до списка 24px
  (`CategoryStep pt-6`), снизу 136px (`PageContent pb-[136px]`) — всё
  уже совпадает с макетом;
- строки: базово совпадают (`ListRow` + `CategoryIcon h-11 w-11` +
  радио 24); расхождения макета — паддинг строки 12px против 24 и `py-2`
  (60px) против `py-1.5` (56px), gap 12 против 16. Асимметрию 12/24 в макете
  стоит подтвердить у владельца до правки `ListRow` (он общий, канон
  DESIGN.md §6 — «не заводить четвёртую анатомию»);
- чип/поиск/нижняя панель — без изменений;
- текст заголовка: «Выберите категорию платежа» (сейчас «Категория платежа»);
  подзаголовок убрать.
